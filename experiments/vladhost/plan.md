# План: Vladhost

## 1. Суть

Бесплатный all-in-one для разработчиков: статический хостинг (потом динамика), веб-файловый менеджер, панель; позже свой DNS, BaaS, CLI/SDK.

| | |
|---|---|
| Код | `experiments/vladhost/` (этот monorepo) |
| Панель | `https://app.vladinc.ru` |
| Сайты юзеров | `https://{site}.{user}.vladinc.ru` (2 уровня) |
| Пример | `blog.john.vladinc.ru` |
| Стек | Go + Gin · PostgreSQL + goose + GORM · Vue 3 + TS + Vite + Naive UI + Pinia + Router + Zod |
| VPS | `37.153.70.33`, 4 ГБ RAM, Ubuntu 24.04 |
| HTTPS | 443 работает снаружи; **per-site LE HTTP-01** |
| DNS | `*.vladinc.ru` (и глубже) → VPS; apex/kupol → `78.108.80.36` |
| Доступ | регистрация **по инвайту**, только бесплатно |
| UI | русский, тёмная dev-тема |
| Ритм | соло, без сроков; MVP без DNS/BaaS |

## 3. Хостинг-схема

```
app.vladinc.ru                 → панель (SPA + /api → Go)
{site}.{user}.vladinc.ru       → статика сайта
  blog.john.vladinc.ru         → /data/vladhost/sites/blog.john/public
```

### DNS

- Majordomo (NS `vladinc.ru`) резолвит **любую глубину** поддоменов на `37.153.70.33` (проверено: 1/2/3 уровня).
- `kupol.vladinc.ru`, apex `vladinc.ru` → `78.108.80.36` (другой сервер — не трогать).
- `app.vladinc.ru` → VPS (в wildcard, ок).
- Для юзерских зон (свой домен) — фаза 7: делегирование на `ns.vladinc.ru`/`ns2` (один IP — SPOF, ок на старте).

### TLS

- Wildcard LE `*.vladinc.ru` покрывает **только один уровень** — **не** подходит для `blog.john.vladinc.ru`.
- **Per-site certbot HTTP-01** на точное имя хоста.
- При создании/деплое сайта: nginx location `/.well-known/acme-challenge/` → `certbot --nginx -d {host}` → renew via certbot.timer.
- `app.vladinc.ru` — отдельный cert (HTTP-01).

### Nginx

- `server app.vladinc.ru` → SPA `frontend/dist` + `proxy_pass` `/api` → Go.
- Regex-default server: `server_name ~^(?<site>[^.]+)\.(?<user>[^.]+)\.vladinc\.ru$` → root `/data/vladhost/sites/$site.$user/public` (+ ACME location).
- Существующие vhosts kupol/registro/api.* — не трогать.


## 5. Модель данных (PostgreSQL, v1)

Миграции: `backend/internal/database/migrations/` (goose, вшиты в бинарь).

| Таблица | Поля | Заметки |
|---------|------|---------|
| `users` | id, email, username, password_hash (bcrypt), role (`admin`/`user`), created_at | уникальны email и username (в нижнем регистре); username — DNS-метка, есть список зарезервированных имён |
| `invites` | id, code, created_by, used_by, used_at, expires_at | одноразовые; использование в одной транзакции с созданием юзера (`FOR UPDATE`) |
| `refresh_tokens` | id, user_id, token_hash (sha256), expires_at, revoked_at | ротация при каждом обновлении; повтор старого токена закрывает все сессии юзера |
| `sites` | id, user_id, slug, host, disk_bytes, status (`empty`/`live`), deployed_at, created_at | host уникален; `(user_id, slug)` уникален; файлы в `{SITES_ROOT}/{host}/public` |


**Квоты:** 500 МБ диск, **1 сайт**/юзер (потом больше).  
**FS:** `/data/vladhost/sites/{host}/public`

**Host генерация:** `{site-slug}.{username}.vladinc.ru` — username из профиля, slug из формы.

## 6. API

Все пути под `/api`, ошибки: `{"error":{"code","message","field?"}}`.

| Метод | Путь | Доступ | Что делает |
|-------|------|--------|------------|
| POST | `/auth/register` | инвайт | создаёт юзера, сразу выдаёт сессию |
| POST | `/auth/login` | — | вход по email или имени |
| POST | `/auth/refresh` | cookie | ротация refresh, новый access |
| POST | `/auth/logout` | cookie | закрывает refresh |
| GET | `/me` | user | текущий пользователь |
| GET/POST | `/invites` | admin | список / создание (1–720 ч, по умолчанию 7 дней) |

| GET/POST | `/sites` | user | список с лимитами / создание `{slug}` |
| DELETE | `/sites/:id` | владелец | удаляет сайт и файлы |
| POST | `/sites/:id/deploy` | владелец | multipart `file` = zip; заменяет сайт целиком |

| GET | `/sites/:id/files?path=` | владелец | список папки (папки первыми) |
| GET/PUT | `/sites/:id/file?path=` | владелец | чтение / сохранение текстового файла (до 2 МБ, только UTF-8) |
| POST | `/sites/:id/files/mkdir`, `/files/rename` | владелец | новая папка / переименование и перенос |
| POST | `/sites/:id/files/upload?path=dir` | владелец | загрузка файла в папку (multipart `file`) |
| DELETE | `/sites/:id/files?path=` | владелец | удаление файла или папки (корень нельзя) |

Файлы: все операции идут через `os.Root` — ядро не даёт выйти за `public` ни через `..`, ни через симлинки. Запись атомарна (временный файл + rename), квота считается по факту, `disk_bytes` пересчитывается после каждой операции.

| POST | `/sites/:id/ftp` | владелец | включает FTP или меняет пароль; пароль в ответе один раз (bcrypt в БД) |
| DELETE | `/sites/:id/ftp` | владелец | отключает FTP, открытые сессии закрываются |

**FTP (фаза 5).** Вместо proftpd сделан встроенный сервер на `ftpserverlib` (`internal/ftpd`). Причины: на сервере стоит
стоковый proftpd без TLS-модуля и SQL (вход по системным аккаунтам, пароли открытым текстом; он не наш — не трогаем),
а квоту диска штатными средствами proftpd без `mod_quotatab` не обеспечить. Свой сервер: принимает и FTPS, и обычный FTP (по умолчанию; `VLADHOST_FTP_ALLOW_PLAIN=false` — только FTPS, тогда без TLS отказ; интерфейс и баннер рекомендуют FTPS),
без root, пути через `os.Root` (те же гарантии, что у файлового менеджера), квота резервируется на каждую запись и
общая для параллельных сессий, пароль на сайт (логин `slug.username`), лимит неудачных входов по IP, отзыв доступа
действует на открытые сессии. Порт 2121 (21 занят proftpd), пассивные порты 50000–50100.

Деплой: в корне архива нужен `index.html` (одна корневая папка снимается автоматически); защита от zip-slip, симлинков, дублей и zip-бомб (лимит считается по факту распаковки); подмена каталога через rename, при ошибке старая версия остаётся.

`/auth/*` ограничены по IP (20 в минуту, всплеск 10).

**Auth:** email+пароль, invite, rate limit.  
Access JWT (15 мин, живёт в памяти вкладки) + refresh (30 дней, httpOnly SameSite=Strict cookie, путь `/api/auth`).  
Первый админ: `VLADHOST_ADMIN_PASSWORD=… vladhost admin create --email E --username U`.  
**Email-подтверждение** отложено до деплоя: нужна настройка exim (SPF/DKIM), иначе письма уйдут в спам.  
Позже: GitHub OAuth, TOTP, passkeys.

Панель — UI-only (без публичного panel-API). BaaS-API — отдельная фаза.

## 13. Почта: SMTP, IMAP и webmail внутри хостинга (план, фаза 6.5)

Цель: у каждого сайта могут быть почтовые ящики, которыми управляют из той же панели; заодно почта решает
подтверждение email при регистрации и рассылку инвайтов.

- **Домены.** Сначала `site.user.vladinc.ru` (ящик `me@blog.john.vladinc.ru`), затем свои домены пользователей
  (нужны MX/SPF/DKIM/DMARC-записи, панель показывает готовые значения; при делегировании зоны на свой DNS —
  публикует сама).
- **Серверная часть.** На сервере уже стоят exim4 и dovecot (используются другими проектами) — их не трогаем.
  Для Vladhost поднимаем отдельные экземпляры на своих портах или общий Postfix/Dovecot с виртуальными ящиками
  в PostgreSQL (`mailboxes`, `aliases`, `domains`): `passdb`/`userdb` через SQL, хранение в Maildir под отдельным
  пользователем `vmail`, квоты Dovecot по ящикам.
- **Порты.** SMTP 25 (приём), 465/587 (отправка с авторизацией), IMAPS 993, POP3S по желанию. Только TLS; сертификат
  `mail.vladinc.ru` выпускается тем же выпускателем, что и для сайтов, и перечитывается без перезапуска.
- **Отправка.** DKIM-подпись (ключ на домен, ротация), SPF, DMARC; лимиты на ящик и на аккаунт (в час/в сутки),
  очередь с повторами, отчёты о недоставке в панель; защита от спама: rspamd (входящие) и запрет открытого relay.
- **Webmail.** Встроенный в панель клиент (Vue: список, чтение, написание, вложения, поиск, папки) через JMAP или
  IMAP-прокси в Go; вход из панели без повторного пароля (одноразовые токены). До готового клиента — SnappyMail или
  Roundcube на отдельном поддомене `mail.vladinc.ru`.
- **Панель.** Раздел «Почта»: ящики, алиасы, пересылка, автоответчик, пароли, квоты, статистика, проверка DNS-записей
  домена (зелёные/красные значки), i18n ru/it, как во всём интерфейсе.
- **Безопасность.** Пароли ящиков — argon2id/bcrypt; отдельные пароли для IMAP-клиентов (app passwords); журнал входов;
  блокировка перебора (fail2ban + счётчики в БД); резервные копии Maildir; ограничение исходящей почты новых аккаунтов
  (защита репутации IP сервера).
- **Риски.** Репутация IP `37.153.70.33` (PTR-запись у хостера, списки блокировок), общий IP с другими проектами,
  ограничения хостера на порт 25. Проверить до старта: исходящий 25, PTR, rDNS.

## 14. FTP: несколько аккаунтов на сайт (план, фаза 5.2)

Сейчас у сайта один FTP-доступ (`slug.username`) с полным доступом. Нужно:

- Таблица `ftp_accounts` (site_id, name, password_hash, root_path, read_only, expires_at, last_login_at, created_at);
  логин `имя@slug.username` или `slug.username+имя`, уникален глобально.
- Ограничение корневой папки (`root_path`) — аккаунт видит только её (через `os.Root` подкаталога), режим «только чтение»,
  срок действия (подрядчик на неделю), отдельные лимиты подключений.
- Панель: список аккаунтов сайта, создание с генерацией пароля (показывается один раз), смена пароля, отключение,
  журнал последних входов и IP; уведомление о входе с нового IP (по желанию).
- Квота диска остаётся общей на сайт/пользователя, учёт по-прежнему через общий счётчик сессий.
- Миграция: существующий доступ становится аккаунтом `main` с полными правами.
- Возможные расширения: SFTP (встроенный на `x/crypto/ssh`), ключи вместо паролей.

## 15. Управление SSL в панели (план, фаза 5.3)

- Раздел «Сертификаты»: список сертификатов пользователя (хост, издатель, срок, статус выпуска/продления), кнопки
  «выпустить заново» и «продлить сейчас», журнал последних попыток и понятные причины отказа (лимиты Let's Encrypt, DNS).
- **Свои домены** (`example.com` → сайт): проверка DNS (A/AAAA/CNAME на сервер), выпуск HTTP-01, добавление в nginx,
  редирект `www` ↔ без `www`; учёт лимитов Let's Encrypt (50 в неделю на домен, 5 неудачных проверок в час) с очередью.
- **Загрузка своего сертификата** (PEM + ключ) с проверкой цепочки, соответствия ключа и срока; хранение ключа только на
  диске сервера под root, в БД — метаданные.
- **HSTS и редиректы**: переключатели «всегда HTTPS» (сейчас включён), HSTS с `max-age` (без `includeSubDomains`).
- **Предупреждения**: письмо и значок в панели за 14 дней до окончания, если автопродление не сработало.
- **Wildcard** для будущего собственного DNS (DNS-01 через API зоны) — снимет лимит «сертификат на сайт».

## 17. Свои домены и смена пароля (сделано)

**Несколько своих доменов на один сайт** (до 5 на сайт, до 10 на аккаунт; `www.example.com` и `example.com` — два домена).
Подключение через A-запись на IP сервера (`VLADHOST_SERVER_IPS`, сейчас `37.153.70.33`):

1. В панели на карточке сайта — «Свои домены»: ввод имени (регистр, точка в конце, IDN → punycode нормализуются).
   Панель показывает, какую запись создать (`A: example.com → 37.153.70.33`), и сразу проверяет DNS.
2. DNS считается верным, если у домена есть A-записи, **все** они указывают на наш IP, и нет AAAA (сервер работает по IPv4).
   Иначе домен ждёт (`pending_dns`), панель объясняет причину: записи нет / указывает на другой IP / есть AAAA / DNS не ответил;
   проверка идёт сама раз в минуту и по кнопке. Домен без верной записи освобождается через 14 дней.
3. При верном DNS ставится заявка выпускателю (`pending_cert`): он повторно проверяет DNS, создаёт server-блок nginx
   `/etc/nginx/vladhost-domains/{домен}.conf` по проверенному шаблону, выпускает сертификат Let's Encrypt (HTTP-01) и
   сообщает результат. Домен становится `active`; ошибка выпуска (`failed`) показывается с текстом и кнопкой «Проверить».
4. Веб-шлюз находит сайт по файлу привязки `/data/vladhost/domains/{домен}` (внутри — адрес сайта); файл пишет панель и
   удаляет при отвязке, содержимое перепроверяется строгим шаблоном.

**Защита от захвата и злоупотреблений:** имена под нашим доменом (`vladinc.ru` и любые поддомены), служебные зоны
(`.local`, `.internal`, `.test`, `.onion`…), IP-адреса, wildcard и публичные суффиксы (`com`, `co.uk`, `github.io`) отклоняются;
домен уникален глобально; владение подтверждает сама A-запись (менять её может только владелец DNS); выпускатель (root)
сам перепроверяет DNS и **не берёт имя, которое уже обслуживает другой проект на сервере** (`server_name` в nginx),
шаблон имени строгий, конфиг nginx проверяется `nginx -t` перед перезагрузкой, а при отказе откатывается; при удалении
домена или сайта убираются привязка, конфиг nginx, сертификат и закрытый ключ. Скрипт выпускателя покрыт тестом
`deploy/test/certs_test.sh` на подменённых certbot/nginx/getent (проверяются отказы, откаты, чужие имена, инъекции в имя).

**Смена пароля** (`POST /api/me/password`, Настройки → «Смена пароля»): проверка текущего пароля, запрет совпадения, правила
длины как при регистрации, лимит попыток как у входа (перебор текущего пароля), проверка Origin. После смены **все**
refresh-токены аккаунта закрываются (другие устройства выходят), текущему выдаётся новая сессия.

## 16. Веб-шлюз сайтов, `.htaccess` и страницы по умолчанию (сделано, фаза 5.1)

Раньше файлы сайтов отдавал напрямую nginx. Теперь nginx держит TLS и сжатие, а файлы отдаёт **веб-шлюз**
(`vladhost web`, служба `vladhost-web`, `127.0.0.1:8091`, отдельный пользователь без доступа к БД и секретам, только чтение
каталога сайтов, `MemoryMax=384M`). Если шлюз недоступен, nginx показывает страницу «временно недоступен».

**Страницы по умолчанию** встроены в шлюз (не лежат в папке пользователя, в FTP их нет), выбираются по `Accept-Language`
(ru/it): «здесь скоро появится сайт» (в сайте нет ни одного видимого файла), 400, 401, 403, 404, 405, 410, 429, 500, 503,
«сайт не найден». Пользователь может заменить любую своей через `ErrorDocument`.

**`.htaccess`** — поддержано подмножество Apache (nginx `.htaccess` не читает, поэтому разбор и выполнение — в шлюзе):

| Область | Директивы |
|---|---|
| Индексы | `DirectoryIndex`, `Options ±Indexes` (листинг с экранированием, без скрытых файлов) |
| Ошибки | `ErrorDocument` (файл сайта, текст, URL) |
| Редиректы | `Redirect` (код, `permanent`, `temp`, `seeother`, `gone`), `RedirectMatch`, `RedirectPermanent`, `RedirectTemp` |
| Rewrite | `RewriteEngine`, `RewriteBase`, `RewriteOptions Inherit`, `RewriteCond` (`-f -d -s -l`, `=`, `<`, `>`, regex, `!`, `[NC,OR]`, переменные `%{...}`, `%N`), `RewriteRule` (флаги `L END R[=код] F G NC QSA QSD NE C S=n`, `$N`, повторные проходы до 10, per-directory как в Apache) |
| Заголовки | `Header [always] set/unset/add/append/merge/edit/edit*` (запрещены `Set-Cookie`, `Location`, `Content-Length`, `Transfer-Encoding` и др.) |
| Кэш | `ExpiresActive`, `ExpiresByType`, `ExpiresDefault` |
| Типы | `AddType`, `ForceType`, `AddEncoding`, `AddDefaultCharset` (по умолчанию UTF-8) |
| Доступ | `Require all denied/granted`, `Order`/`Allow`/`Deny from all`, блоки `<Files>`, `<FilesMatch>`, `<IfModule>` |
| Авторизация | `AuthType Basic`, `AuthName`, `AuthUserFile` (файл в сайте: bcrypt, `$apr1$`, `{SHA}`), `Require valid-user` / `Require user` |

Не выполняются и попадают в замечания (кнопка «Проверить .htaccess» на странице файлов, `GET /api/sites/:id/htaccess`):
`php_*`, `AddHandler`/`SetHandler`, CGI, `RewriteRule [P]` (прокси), `SetEnv*`/`env=`, `RequestHeader`, `<Directory>`, `<If>`,
`Require ip` и остальное. Причина — безопасность: чужой код на общем сервере не исполняется, шлюз не ходит по сети.

**Защита:** регулярные выражения RE2 (линейное время, ReDoS исключён; lookahead и обратные ссылки не поддержаны и попадают
в замечания), размер `.htaccess` ≤ 64 КБ и ≤ 500 директив, ≤ 10 внутренних перезапусков (иначе 500), пути только через
`os.Root` (`..` и симлинки не выводят за сайт), `.htaccess`/`.htpasswd` никогда не отдаются (403), остальные скрытые файлы —
404 (кроме `.well-known`), ErrorDocument/Rewrite не могут раскрыть скрытые файлы или файл за паролем, до 4 одновременных
проверок пароля и 10 неудачных попыток на IP за 10 минут (429), IP клиента берётся из `X-Forwarded-For` только от
локального nginx, методы кроме GET/HEAD/OPTIONS — 405.
