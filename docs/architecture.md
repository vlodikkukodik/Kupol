# КУПОЛ — архитектура, разбор и план улучшений

Разбор от 19.09.2026: что в проекте сделано хорошо, что мешает ему стать лучшим (скорость, надёжность, дизайн,
функции, «реалистичность» архива) и в каком порядке это чинить. Неизменные ограничения автора: **фронтенд — статика на
shared-хостинге, запросы идут через PHP-прокси на том же домене, бэкенд — на VPS.**

Пометка **[решение автора]** — развилка, которую выбирает автор; остальное — рекомендации, готовые к работе.

**Решения автора (19.09.2026), все — рекомендованные варианты:**
- код в git: коммит на каждый законченный шаг и отправка на GitHub; деплой только из коммита;
- фронтенд переходит на TypeScript с типами API из Go и TanStack Vue Query, общий UI-кит — **до** редактора;
- редактор документов (шаг 3.3) — **Tiptap** (WYSIWYG); прежнее решение «поле с разметкой» отменено;
- шрифты: документы на «бумаге» — «машинка», интерфейс — PT Sans, заголовки и штампы — Oswald. Courier Prime оказался без
  кириллицы (в пакете `@fontsource`), поэтому «машинка» — **IBM Plex Mono** (кириллица, OFL);
- **фронтенд пересоздан с нуля** (по решению автора «удалить всё и пересоздать, бэкенд улучшить»): TypeScript, новый дизайн «читальный
  зал», UI-кит `src/ui`, Vue Query; бэкенд не переписывался, а улучшен (контракт типов из Go, журнал событий, `Server-Timing`).

**Сделано из этапа 3.0 (на 19.09.2026, не на бою):** коммиты и CI (типы, eslint, vitest, Go, прокси, копии, сквозные), резервные копии
с проверкой восстановления, типы фронтенда из Go (`make types-check` в CI), журнал событий (`kupol audit`), `Server-Timing` в прокси,
UI-кит и пересозданный интерфейс. Осталось из 3.0: микрокэш гостей и пул соединений на PHP 8.5, приём ошибок браузера
(`/api/client-errors`), внешний монитор доступности.

## 1. Факты, на которые опирается разбор

| Что | Замер / источник |
|---|---|
| Запрос к Go напрямую (`api.kupol.vladinc.ru/health`) | ответ сервера ≈ 50 мс — это чистый пинг, сам Go отвечает мгновенно |
| Тот же запрос через PHP-прокси (`kupol.vladinc.ru/api/health`) | ≈ 120–310 мс: **прокси добавляет 70–260 мс к каждому вызову API** |
| Статика с хостинга (`/`) | ≈ 60 мс: хостинг быстрый, медленна именно дорога хостинг → VPS |
| Почему | PHP живёт один запрос: на каждый вызов API прокси заново открывает TCP и TLS до VPS (3 оборота туда-обратно) |
| PHP на Majordomo | до 8.3 ([Majordomo](https://www.majordomo.ru/business/php-hosting)); переиспользование соединений между запросами (`curl_share_init_persistent`) появилось только в PHP 8.5 ([php.net](https://www.php.net/manual/en/function.curl-share-init-persistent.php)) |
| VPS | 2 vCPU, 4 ГБ ОЗУ (свободно ≈ 2 ГБ — рядом чужие сайты), 47 ГБ диска, Ubuntu 24.04, PostgreSQL 16; процесс `kupol` — 26 МБ |
| Репозиторий | ≈ 17 тыс. строк Go (с тестами), ≈ 5,5 тыс. строк фронтенда — **ни строки не закоммичено** с «Initial commit»; бой отвечает версией `d366aad-dirty` |
| Дублирование стилей | 39 одинаковых объявлений шрифта заголовков и десятки копий стилей `label`/`select` по компонентам |
| Проверка связи | каждая открытая вкладка раз в минуту ходит на `/api/health` через прокси, даже фоновая |

## 2. Что оставить и что поменять в стеке

| Слой | Решение | Почему |
|---|---|---|
| Бэкенд | **Go — оставить** | один бинарник, 26 МБ памяти на общем VPS, хорошая конкурентность для будущих WebSocket; переписывание 17 тыс. строк ничего не даст пользователю |
| БД | **PostgreSQL — оставить** и нагрузить больше: полнотекстовый поиск, очередь задач | отдельные Elasticsearch/Meilisearch/Redis съедят половину свободной памяти общего VPS |
| Прокси | **PHP 8.3 — оставить** минимальным, но научить кэшу и замерам (§3) | ограничение автора; логику в PHP не переносить |
| Фронтенд | **Vue 3 — оставить**; **перейти на TypeScript** [решение автора] | впереди редактор с 15 типами блоков, история версий, рецензии: без типов ошибки формы данных будут ловиться только тестами |
| Типы API | генерировать TypeScript-типы из структур Go ([tygo](https://github.com/gzuidhof/tygo)) | один источник правды без переписывания HTTP-слоя; альтернатива — [Huma](https://github.com/danielgtaylor/huma) с OpenAPI 3.1, но это переделка всех обработчиков |
| Данные на фронте | заменить самодельный `useResource` на [TanStack Vue Query](https://tanstack.com/query) | кэш между экранами («назад» в каталог мгновенно), сброс после изменений в team panel, повторы, отмена |
| Фоновые задачи | [River](https://riverqueue.com/) — очередь на том же PostgreSQL, когда понадобится (PDF, картинки, уведомления, XP) | задачи ставятся в той же транзакции, что и данные; нет новых сервисов |
| PDF | [Typst](https://typst.app/blog/2025/automated-generation/) CLI на VPS вместо headless Chromium | один бинарник, мгновенная вёрстка, своя кириллица; Chromium на общем VPS — сотни мегабайт на экземпляр |
| Картинки | libvips (WebP, превью, удаление EXIF) | быстро и экономно по памяти |

Отвергнуто: Nuxt/SSR (нужен сервер для фронтенда — ломает ограничение), Laravel на хостинге (бизнес-логика уехала бы на
медленный shared), переписывание на Rust/Node (цена без пользы).

## 3. Скорость: как обойти медленную дорогу хостинг → VPS

1. **Замеры в каждом ответе.** Прокси добавляет `Server-Timing` (время соединения, TLS, ответа Go) — видно в DevTools
   и в `check-site.sh`, без догадок.
2. **Микрокэш для гостей на хостинге.** Большинство посетителей — Гражданин (уровень 0): их каталог, лента и открытые документы
   одинаковы для всех. Go помечает такие ответы `Cache-Control: public, max-age=30`; PHP-прокси для GET **без куки сессии**
   отдаёт их с диска хостинга и ходит на VPS не чаще раза в 30 с. Ответы с куками, `Set-Cookie` и всё личное не кэшируются
   никогда — решает Go, прокси только слушается заголовка. Гости получают ответ за время статики, VPS разгружен.
3. **Переиспользование соединений, когда хостинг даст PHP 8.5.** Прокси сам проверяет наличие `curl_share_init_persistent`
   и включает общий пул соединений и TLS-сессий: минус ~2 оборота на каждый вызов. Код совместим с 8.3 уже сейчас;
   стоит спросить поддержку Majordomo о PHP 8.5.
4. **Меньше вызовов.** Проверка связи — только в видимой вкладке и только если за минуту не было других удачных запросов;
   ETag и 304 на документы; предзагрузка документа при наведении на строку каталога.

## 4. Надёжность и процесс — самое срочное

1. **Git.** Вся работа трёх этапов существует только в рабочей папке Codespace. Удаление или сбой Codespace = потеря всего.
   Закоммитить и отправить в `origin` (GitHub уже подключён), дальше — коммит на каждый законченный шаг; деплой только из
   коммита с тегом, чтобы `/health` показывал настоящую версию, а не `-dirty`.
2. **CI (GitHub Actions).** На каждый push: `go vet`, `gofmt`, `go test` с PostgreSQL, тесты PHP-прокси, eslint, vitest,
   Playwright на dev-стеке. Сейчас это делается руками.
3. **Резервные копии — до того, как авторы начнут писать** (в спецификации они в этапе 7, это слишком поздно).
   Каждую ночь `pg_dump` → шифрование [age](https://github.com/FiloSottile/age) → копия **на другой машине**: на shared-хостинге
   (у него свой диск и другой провайдер) по FTPS, хранить 14 дней. Скрипт проверки восстановления в CI: копия, которую ни разу
   не восстанавливали, — не копия.
4. **Журнал аудита.** Роли уже выдаются на бою — нужно видеть, кто кому что выдал; затем публикации, откаты, снятие замков.
5. **Наблюдение.** Внешний монитор доступности (например, Healthchecks.io); приём ошибок браузера на `/api/client-errors`
   в общий лог; просмотр — в админке этапа 7.

## 5. Архитектура кода

**Бэкенд — модульный монолит.** Пакеты по предметам (`accounts`, `documents`, дальше `search`, `social`, `media`, `mail`),
HTTP-слой тонкий. Правила доступа — только в предметных пакетах и только на сервере (как сейчас). Общие решения:
- поиск — таблица `document_search` (документ, блок, уровень, `tsvector` с русской морфологией + `pg_trgm` для шифров),
  обновляется в той же транзакции, что и сохранение; запрос ищет только по блокам уровня ≤ читателя;
- обратные ссылки — таблица `document_links`, из неё «Упоминается в» и граф; фильтр по уровню источника;
- очередь River — с первой задачи, которой не место в запросе.

**Фронтенд.**
- UI-кит `components/ui/` (кнопка, поле, выбор, вкладки, плашка, таблица, окно, страницы) и шкала типографики в токенах —
  вместо копий стилей по экранам. Страница-витрина в dev-сборке и **скриншотные тесты** Playwright (`toHaveScreenshot`),
  чтобы дизайн не «плыл».
- TypeScript + сгенерированные типы API + Vue Query (см. §2) [решение автора].

## 6. Дизайн

Основа («бумага на столе», штампы, печать) удачная; что поднимет уровень:
1. **Разделить шрифты по смыслу.** Машинописный — только внутри документов (на «бумаге»); меню, формы, team panel — чистый
   гротеск [PT Sans](https://fonts.google.com/specimen/PT+Sans) (та же семья, что PT Mono, OFL). Сейчас всё набрано моноширинным —
   длинные формы и таблицы читаются тяжело [решение автора]. Для документов PT Mono заменён на «машинку»
   [IBM Plex Mono](https://fonts.google.com/specimen/IBM+Plex+Mono) (кириллица, OFL): Courier Prime в поставке `@fontsource`
   кириллицы не имеет.
2. **Фактура без картинок:** лёгкий шум бумаги и неровный оттиск штампа через SVG-фильтры (`feTurbulence`), следы маркера
   на зачёркиваниях.
3. **Лист документа:** пропорции A4 на широком экране, поля, колонтитулы; печатная версия (`@media print`) — такая же.
4. **Скелетоны вместо «Загрузка…»,** штамп-анимация на действиях («ОПУБЛИКОВАНО», «ВОЗВРАЩЕНО НА ДОРАБОТКУ»).
5. **Рукописное** — пометки на полях и рукописные заметки шрифтом с кириллицей (например, Marck Script, OFL).

## 7. Реалистичность архива

Дёшево по коду и сильно по ощущению «настоящего дела»:
1. **Гриф-колонтитулы** сверху и снизу листа по уровню документа («НЕСЕКРЕТНО» … «ОСОБОЙ ВАЖНОСТИ»).
2. **Экземпляр №** — у каждого читателя свой номер копии (из номера аккаунта), у гостя «экз. б/н» — как нумерованные копии
   секретных документов.
3. **Архивный шифр** «Фонд · Опись · Дело · Листов» в шапке дела, выводится из типа, отдела, номера и числа страниц.
4. **Лист ознакомления** в конце дела: сколько сотрудников ознакомлено (без имён — история чтения по спецификации закрыта).
5. **Зачёркивания разной длины:** ширина полосы псевдослучайна от положения фрагмента, а не от текста — выглядит живо и не
   раскрывает длину.
6. **«Упоминается в»** — обратные ссылки с учётом допуска; «Картотека» — третий вид каталога карточками.
7. **Требование на выдачу дела** — с «Доступ запрещён» подать ходатайство (в спецификации есть ходатайства на уровни 4–6).

## 8. Редактор (шаг 3.3) [решение автора]

Раньше выбрано «поле с разметкой + кнопки». Для «лучшего» редактора честнее [Tiptap](https://tiptap.dev/docs/editor/getting-started/overview)
(MIT, на ProseMirror, есть Vue 3): настоящий WYSIWYG, свои узлы для всех 15 блоков, отметка «закрыть до уровня N» —
как жирный, зачёркивание видно сразу, работа на телефоне. Цена — ≈ 100 КБ кода редактора (грузится только в team panel)
и больше работы, чем текстовое поле. Серверный формат блоков и вся фильтрация по уровням не меняются.

## 10. Правовое (не юридическая консультация)

Логины и IP-адреса в журналах могут считаться персональными данными (152-ФЗ): политика конфиденциальности на «О КУПОЛЕ»,
срок хранения журналов (например, 30 дней) и удаление данных вместе с аккаунтом (уже есть) — минимум; вопрос об уведомлении
Роскомнадзора автору стоит уточнить отдельно.
