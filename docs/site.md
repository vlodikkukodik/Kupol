# КУПОЛ — спецификация сайта

Итог опроса на 100 вопросов. Канон вселенной — в `docs/organization.md`. Доступы (FTP/SSH) — в `docs/secrets.local.md` (в .gitignore, не коммитить).

Пометка **(предложено)** — решение предложил Claude, автор явно не подтверждал.

## 1. Архитектура и стек
- **Фронтенд:** Vue 3 + Vite + Pinia + Vue Router; сборка статикой, заливается по FTP на shared hosting, домен `kupol.vladinc.ru`. Перетаскивание блоков: SortableJS / vue-draggable-plus (работает на touch). Только современные браузеры (Chrome/Firefox/Safari/Edge, 2 последние версии).
- **PHP-прокси** на том же домене (shared), лежит в `frontend/public/` и уходит вместе со сборкой. Все обычные API-запросы фронта идут через него на Go API.
- **Backend:** Go + Gin/Fiber + GORM, `https://api.kupol.vladinc.ru` на VPS автора. БД: PostgreSQL локально на VPS.
- **Структура репозитория:** `backend/` (Go), `frontend/` (Vue + `public/` с PHP-прокси), `docs/`.
- **Разработка:** локально в этом окружении — docker-compose (Postgres) + `go run` + `vite dev`.
- **Деплой:** скрипты на машине автора — `deploy-front` (сборка + FTP в `www/<папка домена>`) и `deploy-back` (сборка Go + scp + перезапуск systemd на VPS).
- **История URL:** history-режим (`/doc/O-041`) + `.htaccess` с редиректом на `index.html` (автор настроит, нужен mod_rewrite).
- **Логи и мониторинг:** структурные логи Go в файлы с ротацией (journald/logrotate), endpoint `/health`, ошибки видны в супер-админке.
- **Бэкапы:** `pg_dump` + архив `uploads/` на самом VPS по расписанию, хранить последние N копий, скачивание из панели. Плюс экспорт отдельных документов в Markdown/JSON из team panel.

## 2. Безопасность и сеть
- **Сессии (предложено):** серверные сессии в PostgreSQL, идентификатор в httpOnly/Secure/SameSite=Lax cookie на `kupol.vladinc.ru`; прокси пересылает Cookie в Go и возвращает Set-Cookie; мгновенный отзыв при блокировке.
- **Реальный IP через прокси:** PHP ставит `X-Real-IP` и подписывает запрос секретом (HMAC); Go доверяет IP только с валидной подписью.
- **CORS:** обычные запросы только через прокси (CORS не нужен). На api-поддомен разрешены только WebSocket, раздача `uploads/` и upload-POST с одноразовым тикетом (тикет выдаётся через прокси; узкий CORS только на этот эндпоинт).
- **WebSocket** (чат, доска) идёт напрямую на `wss://api.kupol.vladinc.ru` (PHP на shared не проксирует WS); авторизация одноразовым короткоживущим тикетом.
- **Пароли:** минимум 8 символов, bcrypt/argon2, блокировка после N неудач. Персонал и Директорат — дополнительно TOTP (2FA) — **по желанию** (решение автора 2026-09-19; сделано в шаге 3.7, доступно любому вошедшему).
- **Rate limit по умолчанию (настраивается в админке):** вход 5 попыток/15 мин на IP+логин; регистрация 3/час на IP; комментарии 10/час на пользователя; общий API 120 запросов/мин на пользователя/IP.
- **Антибот при регистрации:** rate limit по IP + капча-«анкета» (простой вопрос по вселенной).
- **Фильтрация доступа только на сервере:** закрытые блоки вообще не попадают в JSON для низкого уровня; фронт рисует плашки по метаданным. Тесты на фильтрацию — обязательны.
- **Загрузки:** JPEG/PNG/WebP и аудио mp3/ogg до 20 МБ; хранятся в `uploads/` на VPS. Файлы грузятся напрямую на api-поддомен по одноразовому тикету. Рекомендуется перекодирование в WebP, превью, удаление EXIF (по умолчанию).
- **Пользовательский текст:** простой текст без HTML; допустимы ссылки на документы сайта как кликабельные карточки.
- **Правовое:** короткая политика конфиденциальности на «О КУПОЛЕ» (логин, хэш пароля, IP в логах) + спокойный баннер о технических cookie; дисклеймер о вымысле встроен в главную.

## 3. Уровни доступа
| # | Название | Как получить |
|---|----------|--------------|
| 0 | Гражданин | без регистрации |
| 1 | Посетитель | регистрация |
| 2 | Стажёр | XP (~неделя) |
| 3 | Сотрудник | XP (~месяц) |
| 4 | Надзиратель | выдаёт Высший совет |
| 5 | Куратор | выдаёт Высший совет |
| 6 | Особый Совет | выдаёт Высший совет |
| — | Директорат | только автор через супер-админ панель |

- **Высший совет = Особый Совет** (пользователи уровня 6). Заявки на 4–6: ходатайство из личного дела и приглашения от совета.
- Повышение 2–3: автоматически при пороге XP, записка + анимация штампа «ДОПУСК ПОВЫШЕН».
- Неактивность: серия входов обнуляется, XP и уровень сохраняются.

## 4. Аккаунты и личное дело
- Логин + пароль, вход без почты (решение 19.09.2026 в силе). Почта — **по желанию**, добавлена в шаге 5.1.1 (решение
  автора 22.09.2026, смягчает исходное «без почты»): подтверждается ссылкой из письма, нужна только для уведомлений
  (подтверждение адреса, повышение уровня); её отсутствие ни на что не влияет. Логин: уникальный, 3–24 символа (буквы,
  цифры, `_`, `-`), смена раз в 30 дней через заявку.
- Восстановление: резервный код (показывается один раз при регистрации) + сброс через админа.
- Удаление аккаунта («сдать дело в архив») — полное удаление данных и комментариев.
- «Пропуск» в шапке: ник, уровень, шкала XP; клик открывает личное дело.
- Личное дело: ник, уровень, XP, серия, звание, история отметок и прочитанных, закладки («Взять в работу»), полка грамот/наград, поле ввода кода доступа.
- Другим пользователям по клику на ник видна ограниченная карточка (ник, уровень, звание, грамоты); история чтения и закладки скрыты.
- Достижения/грамоты: например, прочитал 50 документов, серия 30 дней, нашёл скрытый код.

## 5. XP
- Источники: комментарии, оценки, предложения, ежедневный вход/серии, скрытые коды.
- По умолчанию (меняется в админке): вход +10/день (серия даёт бонус), оценка +5 (до 10/день), комментарий +15 (до 3/день), принятое предложение +100. Ориентиры: уровень 2 ≈ 100 XP (~неделя), уровень 3 ≈ 500 XP (~месяц).
- Лимит XP в сутки на источник; серия сбрасывается при пропуске дня. XP штрафами не отнимается.

## 6. Документы
- **Типы и шифры:** Объект `О-041`, Приказ `ПРИКАЗ-1978-12`, Инцидент `ИНЦ-1982-07`, Персонал `ЛД-0157`, Отдел/филиал `ОТД-2` / `ОБ-14`, Протокол эксперимента `ПРОТ-1979-03`, Свидетельские показания `ПОК-1980-22`, Меморандум `МЕМО-N`. Номера `О-№` присваиваются автоматически по порядку при публикации.
- **Адрес:** в базе и интерфейсе кириллица (`О-041`), в URL латиница (`/doc/O-041`, `/doc/PRIKAZ-1978-12`); сервер принимает оба варианта.
- **Хранение:** документ — строка с колонками (шифр, тип, класс, гриф, уровень, статус…); блоки — JSONB-массив (тип, данные, уровень доступа каждого блока).
- **Даты:** в шапке только дата внутри вселенной («дата составления»); реальная дата публикации — только в служебных разделах.
- **Авторство:** в подвале документа указан ник автора из команды.
- **Workflow:** черновик → на проверке → опубликован → архив, с историей версий (автосохранение + снимок при смене статуса, diff по блокам).
- **Блокировка правки:** документ «взят в работу» одним сотрудником (метка «Редактирует: ник»), остальным только чтение; снимается по таймауту 15 минут или вручную.
- **Закрытость:** документ выше уровня читателя невидим в списках и поиске. Прямая ссылка: зависит от флага в шапке — 404 или «Доступ запрещён».
- **Плашки внутри открытых документов:** показывают «ДАННЫЕ УДАЛЕНЫ — допуск не ниже уровня N» (вид: чёрная полоса, штамп, вырез). Скринридер: «засекреченный фрагмент».
- **Скрытые коды (пасхалки):** глобальное поле в личном деле и поле на плашках; верный код открывает тайный документ/блок для аккаунта и даёт XP/грамоту.
- **Печать/PDF:** генерируется на сервере в Go, документ фильтруется по уровню запрашивающего, чёрные плашки.

## 7. Блочный редактор (15+ типов)
Заголовок / абзац / список / цитата; зачернённый текст / плашка с уровнем допуска; шапка досье (номер, класс, гриф, допуск; поля зависят от типа документа); протокол/журнал эксперимента (записи с датами и участниками); изображение с подписью и «наклейкой» (рамка, скрепка, штамп); штамп/печать (СЕКРЕТНО, ИЗЪЯТО, УНИЧТОЖЕНО…); служебная записка / приказ / письмо (бланк с адресатами); вырезка / газета / рукописная заметка / аудио-расшифровка; таблица (например, п.о. по датам); ссылка на другой документ (карточка-связь с превью); разделитель / страница / сноска / приложение. Аудио-запись с плеером — при загрузке mp3/ogg.
- Перемещение блоков, удаление, добавление — в том числе на touch; у части блоков несколько вариантов.
- Редактор полностью адаптивный (работает на телефоне).

## 8. Социальные функции
- **Комментарии:** ветки с ответами, с уровня 1, оформлены как «пометки на полях»; публикуются сразу; кнопка «Жалоба»; автофильтр запрещённых слов; XP сразу.
- **Оценки:** «ознакомлен / одобряю / сомнительно» (канцелярские отметки); публичные счётчики штампами с числами (видит каждый залогиненный).
- **Предложения:** одна форма (идея или замечание). Очередь Редакторов; статусы получено → рассмотрено → принято/отклонено; пользователю приходит записка, XP при принятии.
- **Внутренняя «почта»:** служебные записки от Директората (объявления, «внезапные» сюжетные события); приглашение на 4–6 и решение по ходатайству; ответ на комментарий, решение по предложению, предупреждение/блокировка; повышение уровня и новая грамота.
- **Форум/раздел обсуждений** отдельно от комментариев под документами (запрошен в последнем вопросе; структура, права и уровни доступа — не проработаны).
- **Наказания:** предупреждение → временная блокировка комментариев → бан аккаунта, причина в журнале.

## 9. Навигация и страницы
- **Главная** (предложено): стилизованная «входная дверь» с печатью КУПОЛ, кратким официальным текстом, встроенным дисклеймером, формой входа/регистрации, списком открытых документов уровня 0 и лентой «Поступило в ЦАК» (последние опубликованные, только доступные по уровню).
- **Каталог:** компактный реестр-таблица (№, название, класс, год, п.о.) с переключателем вида «папки».
- **Поиск:** полнотекстовый; текст каждого блока индексируется с его уровнем, запрос идёт только по блокам уровня ≤ уровня пользователя, в выдаче только сниппеты доступных блоков. Фильтры: тип документа, класс, отдел, период, п.о. Теги Архивариуса.
- **Граф связей:** «доска с нитками» — карточки-фотографии соединены красной нитью.
- **«О КУПОЛЕ»** (индексируется): справка (история, структура, отделы), правила сайта (уровни, XP, канон, комментарии), об авторе и контакты, политика конфиденциальности, хронология 1974–наши дни (события задаёт Архивариус: дата, заголовок, текст, уровень допуска события, ссылка на документ; шкала показывает только доступные по уровню).
- **Ошибки:** 404 — «Дело не найдено / изъято», 500 — «Сбой архива», техработы — «Архив закрыт на инвентаризацию».
- **SEO:** индексируются только главная и «О КУПОЛЕ», остальное noindex.
- Нет «случайного документа» и «документа дня».
- **Публичный REST API / RSS:** без ключа — только открытые документы уровня 0; с API-ключом из личного дела — с уровнем этого пользователя.

## 10. Визуал и UX
- Советская канцелярия: бумага, машинописный шрифт, штампы, скрепки. Одна тема — «бумага на столе», без переключения.
- Шрифты — свои файлы на сайте: моноширинная пишмашинка для текста + строгая гарнитура для заголовков и штампов; кириллица обязательна.
- Лёгкие анимации (штамп падает, бумага «выезжает»); звуки выключены по умолчанию, включаются переключателем; уважение `prefers-reduced-motion`.
- Доступность: нормальный контраст на «бумаге» (WCAG AA), клавиатурная навигация с видимым фокусом, alt-текст у картинок.
- Полностью адаптивный интерфейс для читателя и редактора.

## 11. Супер-админ панель (Директорат)
Управление пользователями/уровнями/персоналом; резервные копии БД и файлов (бэкап/восстановление, расписание); настройки XP (пороги, лимиты, награды) без правки кода; глобальные настройки (режим обслуживания, баннер-объявление, вкл/выкл регистрации); журнал аудита (кто, когда, что менял); просмотр ошибок сервера.

## 12. Team panel (персонал)
Роли выдаёт Директорат: **Автор**, **Редактор**, **Модератор**, **Архивариус**.
- Рецензия: комментарии, привязанные к блоку + вердикт (принять / вернуть на доработку / отклонить). Публикация вручную (без планировщика).
- Библиотека: шаблоны документов и наборы блоков; медиатека с тегами; глоссарий/справочник канона.
- Линтер канона при отправке на проверку: битые ссылки на документы и дубли номеров О-№.
- Предпросмотр «глазами уровня N» (переключатель 0–6; бэкенд реально фильтрует).
- Доска заданий + чат по WebSocket. Дашборд: мои черновики и замечания Редактора; очередь на проверку (Редакторам) и жалобы (Модераторам); статистика по моим документам (просмотры, отметки, комментарии); задачи и непрочитанные сообщения чата.
- Экспорт отдельных документов в Markdown/JSON.

## 13. Старт проекта
- Пустой архив, контент добавляет автор после запуска.
- Порядок этапов (согласован): 0 скелет и проверка хостинга → 1 аккаунты → 2 ядро документов с серверной фильтрацией по уровню →
  3 редактор и team panel (**MVP = этапы 0–3**) → 4 социальное и XP → 5 поиск, граф, PDF, «О КУПОЛЕ» → 6 реалтайм и загрузки →
  7 админка, бэкапы, API-ключи и RSS, форум.
- Этап 0 выполнен: скелет (Go API, PHP-прокси, Vue), деплой-скрипты, проверки инфраструктуры — см. `docs/dev.md`, `docs/deploy.md`.
- Этап 1 выполнен: регистрация без почты (логин + пароль + анкета), вход, серверные сессии, argon2id, резервный код, восстановление
  доступа, лимиты частоты, «пропуск» в шапке, личное дело, смена пароля, «сдать дело в архив», админ-команды `kupol user` — см.
  `docs/dev.md`, раздел «Аккаунты и сессии». Сознательно отложено до своих этапов: шкала XP (нужны пороги из админки), TOTP для
  персонала (роли — этап 3), смена логина через заявку (этап 7), грамоты и закладки (этап 4). Принятые на этапе решения:
  уровень при регистрации — 1 (Посетитель); логин — латиница или кириллица без смешения, с резервом слов; сессия 30 дней
  скользящая, до 90 дней абсолютная; счётчики лимитов — в памяти процесса; Директорат и уровни 4–6 — только через CLI на сервере.

- Этап 2 выполнен: документы с серверной фильтрацией по уровню допуска, все типы блоков без файлов (`image`/`audio` — этап 6),
  каталог («Реестр» и «Папки», фильтры, сортировка, пагинация), страница документа, «Доступ запрещён», лента «Поступило в ЦАК»,
  загрузка JSON-файлом и командой `kupol doc ...` — см. `docs/documents.md`. Принятые на этапе решения: ввод документов — JSON-файл
  + CLI (редактор — этап 3); уровень 7 — «только Директорат», Директорат видит всё, включая черновики; поля Объекта — категория
  (человек/существо/место), статус содержания (содержится/утрачен/уничтожен/изучается), место обнаружения, класс 1–5, п.о., отдел,
  год; шифры кириллицей в каноне и латиницей в адресе (`О-041` → `/doc/O-041`), терпимый разбор ввода; автономер `О-№` при
  публикации объекта без шифра; ссылка на недоступный документ не раскрывает ни шифр, ни название, ни примечание; реальная дата
  публикации читателям не показывается; чтения пишутся в `document_reads` с самого начала.

- Этап 3 (в работе): решения автора — несколько ролей на человека; публикует Редактор (свои документы не публикует; Директорат —
  всегда); правка опубликованного «на месте» только Редактором и Директоратом, каждая правка — снимок с откатом; текст блоков —
  поле с разметкой `**жирный**`, `_курсив_`, `[[3|закрытое]]` и кнопки; в этап входят шаблоны и наборы блоков, глоссарий,
