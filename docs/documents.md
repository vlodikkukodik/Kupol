# КУПОЛ — документы (этап 2)

Как устроены документы, как их загружать до появления редактора (этап 3) и как сервер решает, что показать читателю.
Канон вселенной — `docs/organization.md`, общая спецификация — `docs/site.md`.

## Главное правило

**Закрытого от читателя не существует в ответе сервера.** Фильтрация — на сервере, а не в интерфейсе: ответ собирается заново
из белого списка полей, поэтому ни текста, ни названия, ни длины закрытого фрагмента в нём нет. Браузер получает только метку
«здесь закрыто, нужен допуск N».

## Уровни допуска

| Уровень | Кто | Замечание |
|---|---|---|
| 0 | Гражданин (гость) | не вошёл |
| 1–6 | Посетитель … Особый Совет | выдаётся регистрацией (1) и командой `kupol user set-level` |
| 7 | только Директорат | вне шкалы 1–6: Директорат видит **всё**, включая черновики |

Документ и каждый его блок (и каждый фрагмент текста) имеют свой уровень. Уровень блока — не ниже уровня документа.
Читатель с допуском L видит то, у чего уровень ≤ L.

## Формат файла

Один документ или пакет `{"documents": [...]}`. Неизвестные поля — ошибка (опечатка не должна тихо теряться); размер до 4 МиБ.

```json
{
  "code": "О-041",
  "type": "object",
  "title": "Название документа",
  "status": "published",
  "level": 0,
  "direct_link": "not_found",
  "grif": "Форма КУПОЛ-1",
  "composed": { "year": 1979, "month": 3, "day": 14 },
  "props": {
    "danger_class": 3,
    "deviation_points": 42,
    "department": "ОТД-2",
    "category": "entity",
    "containment_status": "contained",
    "discovery_place": "Заброшенная насосная станция"
  },
  "blocks": [
    { "id": "head", "type": "dossier_header", "data": {} },
    { "id": "intro", "type": "paragraph", "data": { "text": "Текст." } },
    { "id": "secret", "type": "paragraph", "level": 4, "data": { "text": "Только с допуском 4." } }
  ]
}
```

| Поле | Значение |
|---|---|
| `code` | шифр (см. ниже). Можно не указывать **только** у объекта со статусом `published`: номер «О-№» присвоится сам |
| `type` | `object`, `order`, `incident`, `personnel`, `unit`, `protocol`, `testimony`, `memo` |
| `title` | 1–300 знаков |
| `status` | `draft` (по умолчанию), `review`, `published`, `archived`. Читатели видят только `published` |
| `level` | 0–7, по умолчанию 0 |
| `direct_link` | что видит читатель без допуска, открывший документ по прямой ссылке: `not_found` (по умолчанию — 404, существование не раскрывается) или `forbidden` («Доступ запрещён», указан нужный допуск) |
| `grif` | гриф, по умолчанию «Форма КУПОЛ-1» |
| `composed` | дата составления **внутри вселенной**; месяц и день необязательны (день без месяца нельзя); год 1900–2099 |
| `props` | свойства **только у объекта**: класс опасности 1–5, п.о. (≥ 0), отдел (шифр `ОТД-2`/`ОБ-14`), категория `person`/`entity`/`place`, статус содержания `contained`/`lost`/`destroyed`/`studying`, место обнаружения |
| `blocks` | до 500 блоков; `id` — латиница, цифры, `_`, `-` (по умолчанию `b1`, `b2` … по положению; для блоков, на которые что-то ссылается, задавайте явно); `level` необязателен |

Реальная дата публикации служебная и читателям не показывается — только дата составления.

### Шифры

| Тип | Канон (кириллица) | Адрес (латиница) |
|---|---|---|
| Объект | `О-041` | `/doc/O-041` |
| Приказ | `ПРИКАЗ-1978-12` | `PRIKAZ-1978-12` |
| Инцидент | `ИНЦ-1982-07` | `INC-1982-07` |
| Личное дело | `ЛД-0157` | `LD-0157` |
| Отдел / филиал | `ОТД-2`, `ОБ-14` | `OTD-2`, `OB-14` |
| Протокол | `ПРОТ-1979-03` | `PROT-1979-03` |
| Показания | `ПОК-1980-22` | `POK-1980-22` |
| Меморандум | `МЕМО-5` | `MEMO-5` |

Разбор терпим к раскладке, регистру и виду дефиса: `о-41`, `O-041`, `О–041` — один и тот же документ. Числа приводятся к
канону: `О-41` → `О-041`, `ПРИКАЗ-1978-2` → `ПРИКАЗ-1978-02`, `ЛД-157` → `ЛД-0157`. `О-0` (Праисточник) остаётся `О-0`
и в автонумерацию не входит. Открытый в браузере адрес всегда приводится к каноническому латинскому.

**Автономер.** Объект без шифра при публикации получает следующий свободный `О-№` (под блокировкой в БД: два одновременно
опубликованных объекта не получат один номер). CLI печатает присвоенный номер.

## Типы блоков

Реализованы все, кроме блоков с файлами: `image` и `audio` отклоняются с сообщением «появится вместе с загрузкой файлов (этап 6)».

**Форматированный текст (`Rich`)** — строка (`"Текст"`) либо список фрагментов
`[{"text": "…", "bold": true, "italic": true, "level": 3}]`. Фрагмент с `level` выше допуска читателя приходит как
`{"redacted": true, "level": 3}` — без текста и без длины; интерфейс рисует чёрную полосу фиксированной ширины.

| `type` | `data` |
|---|---|
| `heading` | `depth` 1–3 (на странице h2–h4: h1 занят названием), `text` |
| `paragraph` | `text` (Rich) |
| `list` | `ordered` (bool), `items` — список Rich |
| `quote` | `text` (Rich), `source` |
| `dossier_header` | `{}` — шапка досье строится из свойств самого документа; не более одной |
| `experiment_log` | `title`, `entries`: `[{date, participants: [..], text (Rich)}]` |
| `stamp` | `text` (до 40 знаков), `tone` `red`/`ink`, `tilt` −15…15 |
| `memo` | `kind` `memo`/`order`/`letter`, `number`, `date`, `from`, `to: [..]`, `subject`, `body`: список Rich, `signature` |
| `clipping` | `kind` `newspaper`/`handwritten`/`transcript`; для газеты и рукописи `paragraphs`, для расшифровки записи `lines`: `[{speaker, text}]`; `title`, `source`, `date` |
| `table` | `caption`, `columns`, `rows` (ячейка — Rich; число ячеек равно числу столбцов) |
| `doc_link` | `code` (шифр), `note` |
| `divider` | `style` `line`/`stars` |
| `page` | `number` |
| `footnote` | `mark`, `text` (Rich) |
| `appendix` | `number`, `title` |

### Как закрытое выглядит для читателя

- **Блок выше допуска** заменяется меткой `{"type": "redacted", "data": {"level": N}}` — без `id`, типа и данных. Подряд идущие
  закрытые блоки одного уровня сливаются в одну метку. Интерфейс: тёмная плашка «Данные удалены — допуск не ниже уровня N».
- **Фрагмент текста выше допуска** — `{"redacted": true, "level": N}`.
- **Ссылка `doc_link`**: если читатель не может открыть цель (её нет, она выше допуска, это черновик), ответ — только
  `{"available": false}`: ни шифр, ни название, ни примечание автора не раскрываются. Иначе — шифр, адрес, название, тип и примечание.
- **Документ выше допуска целиком** — по `direct_link`: `404 not_found` или `403 access_denied` с `required_level` и
  `required_level_name`. Черновики, проверка и архив для всех, кроме Директората, — всегда 404.

## Загрузка документов

Пока нет редактора, документы загружает автор командой на сервере (на VPS: `sudo kupol-admin doc ...`):

```bash
kupol doc import [--dry-run] [--author <логин>] файл.json...   # создаёт и обновляет по шифру
kupol doc export <шифр>                                          # тот же формат, что принимает import
kupol doc list [--status draft|review|published|archived]
kupol doc set-status <шифр> <статус>
kupol doc delete <шифр> --yes
```

- Загрузка **атомарна**: если хоть один документ пакета не прошёл проверку, не сохраняется ничего. Замечания выводятся сразу
  все, с путями (`documents[2].blocks[4].data.text`).
- `--dry-run` проверяет и показывает, что будет создано или обновлено, ничего не сохраняя.
- Повторная загрузка документа с тем же шифром обновляет его (растёт `revision`). Экспорт → правка → импорт — рабочий круг.
- Предупреждения (не ошибки): ссылка на документ, которого пока нет в архиве; отдел, которого нет в архиве.
- При первой публикации проставляется реальная `published_at`.
- Тот же формат принимает и интерфейс команды («Документы» → «Загрузить из файла»; `docs/dev.md`, шаг 3.6), но иначе: один документ,
  статус из файла не берётся, создаётся **черновик** загрузившего. Скачать документ в этом формате — «Скачать JSON» на странице документа.

## API для читателя

Всё — `GET`, без вошедшего пользователя работает как гость (уровень 0).

| Путь | Что |
|---|---|
| `GET /api/documents` | страница каталога |
| `GET /api/documents/summary` | сводка для фильтров и «папок»: `total`, `types[{type,name,count}]`, `departments[{code,count}]`, `classes[{class,count}]` — считаются только доступные читателю |
| `GET /api/documents/recent?limit=8` | лента «Поступило в ЦАК» (до 50) |
| `GET /api/documents/:шифр` | документ; `:шифр` — в любой записи |

Параметры каталога: `type`, `class` (1–5), `department` (`ОТД-2`), `category`, `containment`, `year_from`, `year_to`, `status`
(только Директорату), `sort` (`code` — по умолчанию, `title`, `year`, `class`, `deviation`, `published`), `order` (`desc`),
`page`, `per_page` (по умолчанию 50, до 100). Ответ: `{items, total, page, per_page, pages}`. Шифры сортируются **естественно**
(`О-9` раньше `О-10`) — за это отвечает коллация PostgreSQL `kupol_natural` (ICU `ru-u-kn-true`). Неверные параметры — `400` с
понятным сообщением, а не пустой список.

В каталоге читатель не видит ни одной строки выше своего допуска и не может узнать об их существовании по счётчикам.
Чтения документов пишутся в `document_reads` (основа будущей статистики и «прочитано»).

## Интерфейс

- `/catalog` — «Реестр» (таблица с сортировкой по заголовкам, `aria-sort`) и «Папки» (по типам). Всё состояние — в адресе:
  `/catalog?type=object&class=3&dept=ОТД-2&from=1970&to=1990&sort=year&order=desc&page=2`. Ссылкой можно поделиться, «назад» работает.
- `/doc/<шифр>` — документ. Фокус после перехода — на названии; заголовок вкладки: шифр и название; для отказа — «Доступ запрещён»
  и «Дело не найдено».
- Главная — лента «Поступило в ЦАК» (8 последних); «Каталог» — в боковом меню (бургер в шапке).

## Как это проверяется

- `backend/internal/documents/security_test.go` — на каждое поле каждого типа блока ставится метка секрета, документ читается на
  каждом уровне 0–7, и **ни одной метки выше допуска нет** ни в ответе, ни в сериализованном JSON; то же на 300 случайных документах.
  Мутационные проверки (блок открывается уровнем раньше, `doc_link` раскрывает цель, потерян фильтр по статусу) ловятся тестами.
- `service_test.go`, `catalog_test.go`, `httpapi/documents_test.go` — матрица «статус × уровень × режим × читатель», атомарность
  импорта, гонка автономера, фильтры, сортировки, пагинация.
- `frontend/e2e/documents.spec.js`, `catalog.spec.js`, `a11y.spec.js` — Chromium на настоящем стеке: фикстуры
  `frontend/e2e/fixtures/pack.json` загружаются командой `kupol doc import` (`e2e/global-setup.js`), пользователи создаются
  настоящей регистрацией и `kupol user set-level`; для каждого уровня 1–6 и Директората проверяются и ответ API, и экран.
  После прогона фикстуры удаляются.
