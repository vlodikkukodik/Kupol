# КУПОЛ — разработка

Схема запроса (в dev идёт тем же путём, что на проде):

```
браузер ──► Vite (dev) / Apache (прод) ──► PHP-прокси ──► Go API ──► PostgreSQL
                     kupol.vladinc.ru            api.kupol.vladinc.ru (nginx на VPS)
```

Прямо на api-поддомен из браузера ходят только WebSocket, загрузки файлов и раздача `uploads/` (этапы 5–6);
все обычные запросы идут через PHP-прокси (`/api/...`).

## Что нужно

Go 1.27+, Node 24+, PHP 8.3+ (CLI, с cURL), Docker (PostgreSQL и проверки инфраструктуры), `jq`, `curl`.
Для `make test-infra` ещё `lftp` и `sshd`; для браузерных тестов — Chromium (`npx playwright install chromium`).

## Быстрый старт

```bash
make env      # создать .env (секрет прокси генерируется)
make dev      # всё сразу; сайт на http://127.0.0.1:5173, Ctrl+C останавливает
```

`make help` — список всех команд.

## Go API

- `kupol serve` — запуск (сам применяет миграции), `kupol migrate up|down|status`, `kupol user ...`, `kupol doc ...`,
  `kupol audit ...` (журнал событий), `kupol version`.
- **Контракт с фронтендом.** Ответы и запросы API — именованные экспортируемые структуры (`httpapi/api_types.go`, DTO в
  `auth.go`, `team.go`, `team_documents.go`, данные блоков `documents.Out*`); `gin.H` в обработчиках не используется. `make types`
  (tygo, версия закреплена в Makefile) превращает их в `frontend/src/api/generated/*.ts`; расхождение ловит CI (`make types-check`).
  Теги `tstype` (`",required"`, `",extends"`, `"unknown"`) уточняют вывод там, где по коду Go тип не очевиден.
- **Журнал событий** (`internal/audit`, таблица `audit_events`, миграция 0006): выдача и снятие ролей, снятие чужого замка, откат и
  правка опубликованного документа, смена пароля, восстановление доступа, сброс пароля автором. Запись делается в той же транзакции,
  что и действие; в подробностях нет ни паролей, ни кодов, ни содержимого документов. Ссылки на людей — `ON DELETE SET NULL`:
  когда аккаунт «сдан в архив», запись остаётся, а имени в ней нет. Просмотр: `kupol audit [--limit N] [--action событие] [--doc id]`
  (на VPS — `sudo kupol-admin audit ...`); страница журнала — с админкой (этап 7).
- Новая миграция — файл `backend/internal/database/migrations/NNNN_название.sql` с `-- +goose Up` / `-- +goose Down`.
- Формат ошибок: `{"error":{"code":"...","message":"...","request_id":"...","fields":{...},"retry_after":N}}`.
  Фронтенд ориентируется на `code`; `fields` — ошибки по полям формы, `retry_after` (секунды) — для 429.
- `GET /health` (напрямую, для мониторинга) и `GET /api/health` (через прокси): статус и связь с БД; 503, если БД недоступна.
- Режим обслуживания (этап 7) должен отвечать `503` с кодом `maintenance` — фронтенд по нему показывает «Архив закрыт на инвентаризацию».

### Аккаунты и сессии (этап 1)

| Метод и путь | Что делает | Ответ |
|---|---|---|
| `GET /api/auth/session` | кто я; для гостя `{"user": null}` (не 401, чтобы не сорить ошибками в консоли) | 200 |
| `GET /api/auth/captcha` | вопрос анкеты для регистрации `{id, question}`, ответ принимается один раз, 10 минут | 200 |
| `POST /api/auth/register` | `{login, password, captcha_id, captcha_answer}` → аккаунт, вход, кука; **резервный код показывается один раз** | 201 `{user, backup_code}` |
| `POST /api/auth/login` | `{login, password, totp?}` → кука; `totp` нужен, только если включён код из приложения (см. ниже) | 200 `{user}` / 401 `invalid_credentials` / 401 `totp_required` / 422 `totp_invalid` / 429 |
| `POST /api/auth/logout` | завершает текущую сессию (идемпотентно) | 204 |
| `POST /api/auth/restore` | `{login, backup_code, new_password}` → новый пароль, **новый** резервный код, все прежние сессии завершены; при включённом коде из приложения сессии **не** создаётся (`user: null`) | 200 `{user \| null, backup_code}` |
| `POST /api/me/password` | `{current_password, new_password}`; остальные сессии завершаются, текущая остаётся | 204 |
| `DELETE /api/me` | `{password}` — «сдать дело в архив»: полное удаление аккаунта | 204 |

Как это устроено:

- **Сессии** — серверные, в PostgreSQL. В куке `kupol_session` лежит случайный токен (32 байта), в БД — только его SHA-256.
  Кука `HttpOnly`, `SameSite=Lax`, `Path=/`, без `Domain` (только `kupol.vladinc.ru`), `Secure` — в prod. Срок скользящий 30 дней
  (продлевается при активности не чаще раза в 5 минут), но не дольше 90 дней от входа. Удаление строки завершает сессию мгновенно.
- **Пароли** — argon2id (19 МиБ, 2 прохода) в PHC-формате: параметры можно усиливать, старые хеши пересчитываются при входе.
  Перед хешированием пароль нормализуется NFKC. Число одновременных хешей ограничено (память общего VPS). Для несуществующего
  логина считается «холостой» хеш: по времени ответа логин не угадать.
- **Логин** — 3–24 символа, латиница или кириллица (не вперемешку: иначе можно подделать «Kуратор» с латинской K), цифры, `_`, `-`;
  уникален без учёта регистра; есть список зарезервированных слов. Правила проверяются и на сервере (`accounts/rules.go`), и на
  клиенте (`src/lib/rules.ts`) по **общему файлу векторов** `backend/internal/accounts/testdata/login_rules.json`.
- **Резервный код** — `KUPOL-XXXX-XXXX-XXXX-XXXX` (80 бит), в БД только argon2id-хеш; при восстановлении заменяется новым.
- **Анкета вместо капчи** — вопрос по вселенной (ответ читается на главной странице). Вопрос одноразовый: неверный ответ его гасит.
  Банк вопросов — `accounts/captcha.go`; при изменении текста главной проверьте, что вопросы остаются отвечаемыми.
- **Лимиты** (спецификация §2): вход — 5 неудач на IP+логин и 15 на логин с любых IP за 15 минут, после чего вход блокируется
  даже с верным паролем; регистрация — 3 в час на IP; API — 120 запросов в минуту на пользователя (гость — на IP); перед сессией
  действует грубый лимит по IP в 10 раз выше. Смена пароля, удаление и восстановление считаются теми же счётчиками, что и вход
  (украденной сессией пароль не перебрать). Счётчики в памяти процесса. Ответ 429 несёт `Retry-After`.
- **CSRF** — изменяющие запросы (POST/PUT/PATCH/DELETE) принимаются только с `Origin` = `KUPOL_SITE_ORIGIN`; без `Origin` — только
  если нет куки сессии (curl, скрипты). Тело — строго `application/json`, до 16 КиБ, неизвестные поля отвергаются.
- **Админ-команды** (Директорат и уровни 4–6 выдаются только здесь до появления админки):

  ```bash
  kupol user show <логин>
  kupol user set-level <логин> <1-6>
  kupol user set-directorate <логин> on|off
  kupol user set-role <логин> <author|editor|moderator|archivist> on|off   # роли команды (этап 3)
  kupol user reset-password <логин>      # выводит временный пароль, завершает все сессии
  kupol user reset-totp <логин>          # снимает код из приложения и одноразовые коды (телефон и коды потеряны)
  ```

  На VPS: `sudo kupol-admin user ...` (`deploy/server/kupol-admin.sh`).
- Фоновая уборка: просроченные сессии и вопросы анкеты — раз в час, ключи ограничителя — раз в минуту.
- Отложено до своих этапов: шкала XP в «пропуске» (нужны пороги из админки), смена логина через заявку (этап 7), грамоты и закладки
  в личном деле (этап 4).

### Код из приложения — TOTP (шаг 3.7)

**По желанию**, а не обязательно (решение автора): вход без кода продолжает работать, пока человек сам не включит защиту в личном деле
(раздел «Код из приложения»). Доступно любому вошедшему, не только персоналу. Стандарт RFC 6238: HMAC-SHA1, 6 цифр, шаг 30 секунд — то, что
понимают Google Authenticator, Aegis, 1Password и др. Сервис — `accounts/totp.go` (чистые функции: код, проверка, шифрование, одноразовые коды)
и `accounts/totp_service.go` (сценарии); миграция `0010_totp.sql`.

| Метод и путь | Что делает | Ответ |
|---|---|---|
| `GET /api/me/totp` | включена ли защита, сколько одноразовых кодов осталось | 200 `{enabled, recovery_left}` |
| `POST /api/me/totp/setup` | `{password}` → новый секрет и ссылка `otpauth://` (её кодирует QR); **защита ещё не включена**, прежний неподтверждённый секрет заменяется | 200 `{secret, uri}` |
| `POST /api/me/totp/enable` | `{code}` — первый код из приложения включает защиту; в ответ **10 одноразовых кодов (показываются один раз)**; остальные сессии завершаются | 200 `{recovery_codes}` |
| `POST /api/me/totp/disable` | `{password, code}` — код из приложения или одноразовый | 204 |
| `POST /api/me/totp/recovery-codes` | `{password, code}` — новые одноразовые коды, прежние перестают действовать | 200 `{recovery_codes}` |

- **Вход.** Сначала пароль. Верный пароль без `totp` → `401 totp_required` (после проверки пароля: постороннему не раскрывается, включена ли защита);
  неверный пароль — обычная `invalid_credentials`. Верный пароль и неверный код → `422 totp_invalid`. Принимается код из приложения (`123456` или `123 456`)
  **или** один из одноразовых кодов (`abcde-fghij`, регистр и дефис не важны).
- **Перебор.** Неверный код — такая же неудача входа, как неверный пароль (5 на IP+логин и 15 на логин за 15 минут, затем 429 даже с верным кодом).
  Верный пароль без кода счётчики **не** сбрасывает: иначе код можно было бы перебирать «бесплатно» (тест `WrongCodesCount…`, мутация ловится).
- **Повтор.** Шаг времени, по которому принят код, запоминается (`users.totp_last_step`, условный `UPDATE`): тот же код второй раз не проходит, и два
  одновременных входа с одним кодом не пройдут оба (тест с восемью горутинами). Допускается шаг назад и вперёд (часы телефона).
- **Хранение секрета.** Серверу секрет нужен открытым, поэтому он зашифрован: AES-256-GCM, ключ выводится HMAC-SHA256 из общего секрета сервера
  (`KUPOL_PROXY_SECRET`, отдельной настройки нет), шифртекст привязан к номеру пользователя — перенос строки другому пользователю не расшифруется.
  **Смена `KUPOL_PROXY_SECRET` делает сохранённые секреты нечитаемыми:** вход по коду из приложения перестанет работать (одноразовые коды — хеши,
  они продолжают), администратор может снять защиту `kupol user reset-totp`, люди подключат её заново. Одноразовые коды в БД — SHA-256 (код случайный,
  50 бит; перебор ограничен теми же лимитами входа), каждый гасится условным `UPDATE`.
- **Восстановление по резервному коду** меняет пароль, но **не заменяет** код из приложения: сессия не создаётся, человек входит обычным путём — с новым паролем
  и кодом. Иначе резервный код обходил бы вторую защиту. Новый резервный код такой человек видит на самом экране «Восстановление доступа».
- **Потеряны и телефон, и одноразовые коды** — `sudo kupol-admin user reset-totp <логин>` (запись в журнале, `account.totp_reset`). Журнал аудита ведёт
  включение, выключение, выпуск новых кодов и вход по одноразовому коду (`account.totp_*`).
- **Интерфейс.** `TotpPanel.vue` в личном деле: подключение в три шага (пароль → QR и первый код → одноразовые коды; окно с кодами не закрывается, пока
  не отмечено «сохранил(а)»), новые коды, выключение; `LoginForm.vue` — второй шаг входа; QR рисует `QrCode.vue` (библиотека `qrcode-generator` даёт
  только матрицу, картинка — SVG на месте, секрет никуда не уходит; чёрное на белом в любой теме). Тест `tests/totp.test.ts` растеризует нарисованный QR
  и **читает его сканером jsQR**: ссылка возвращается без искажений.
- **Тесты.** Векторы RFC 6238, окно и повтор, шифрование (чужой пользователь, подделка, другой секрет сервера), весь жизненный цикл, гонки, HTTP-уровень со
  своей независимой записью RFC 6238 в тесте, откат миграции; `e2e/totp.spec.js` (4) — подключение, вход, одноразовые коды, новые коды, выключение,
  восстановление, блокировка после пяти неверных кодов, телефон 375 px и axe. Мутации (нет защиты от повтора; пароль без кода сбрасывает счётчики; восстановление
  обходит код; шифртекст не привязан к пользователю) ловятся.

### Роли и права команды (этап 3)

Роли — Автор, Редактор, Модератор, Архивариус; у человека их может быть несколько (таблица `user_roles`, миграция 0004).
Директорат — не роль, а флаг пользователя: он подразумевает все роли и все права и выдаётся только командой на сервере.

- **Права выводит сервер.** `accounts/roles.go` хранит таблицу «роль → права» (`User.Can`); в ответах `/api/auth/session`, входа и
  регистрации у пользователя есть `roles` и готовый список `capabilities`. Интерфейс ничего из ролей не выводит (`auth.can('...')`).
  Права читаются из БД на каждый запрос, поэтому выданная или снятая роль действует сразу, на открытой сессии.
- **Кто что может** (тест `TestRoleCapabilitiesMatrix` держит таблицу отдельно от кода):

  | Право | Автор | Редактор | Модератор | Архивариус | Директорат |
  |---|:-:|:-:|:-:|:-:|:-:|
  | `team_panel` — войти в панель команды | ✓ | ✓ | ✓ | ✓ | ✓ |
  | `write_drafts` — создавать и править черновики | ✓ | ✓ | | | ✓ |
  | `review` — проверять, выносить вердикт | | ✓ | | | ✓ |
  | `publish` — публиковать (не свои) | | ✓ | | | ✓ |
  | `edit_published` — править опубликованное на месте | | ✓ | | | ✓ |
  | `manage_glossary`, `manage_templates`, `manage_timeline` | | ✓ | | ✓ | ✓ |
  | `manage_team` — выдавать и снимать роли | | | | | ✓ |

### Документы (этап 2)

### Предпросмотр «глазами уровня N» (шаг 3.4)

`POST /api/team/documents/:id/preview`, тело `{"level": 0–7, "content": {…}}` (`content` необязателен: без него — сохранённое). Ответ —
`PreviewResult`: `access` (`open` | `not_found` | `denied`), `required_level`, `document` (форма как у обычного чтения) и `problems`.

- **Не может разойтись с боем.** Сервер собирает ответ тем же кодом, что `Service.Get`: `RenderBlocks`, разбор ссылок, правила доступа к
  документу (`outDocument` — общая функция). Читатель уровня N — `previewViewer(N)`: 0 — Гражданин, 1–6 — пользователь, 7 — Директорат.
  Тесты сверяют предпросмотр с `Get` на всех уровнях и проверяют, что закрытое в ответ не попадает вовсе (а не «скрыто стилями»).
- **Права.** Видит тот, кто вправе видеть документ в team panel (менять его не нужно); чужой черновик — 404, как и сам документ.
- **Ничего не пишет:** ни редакции, ни снимка, ни записи о прочтении. Статус документа не учитывается (показ «как опубликованного»).
- **Неполный черновик не мешает.** Блоки с замечаниями в предпросмотр не входят, замечания приходят в `problems` (`blocks[3]…`), а
  документ-уровневые поля берутся из содержимого, если они верны сами по себе, иначе — как сохранено.
- **Интерфейс:** вкладка «Предпросмотр» страницы документа (`components/team/DocumentPreview.vue`), уровень — в адресе
  (`?tab=preview&level=2`), запрос с паузой 400 мс после правки; лист рисует общий `components/document/DocumentPaper.vue` — тот же, что при
  чтении. Вкладка «Документ» только скрывается (`v-show`): редактор остаётся в памяти, не теряются курсор и история отмены.

### Ход документа и рецензия (шаг 3.5)

Статусы прежние: черновик → на проверке → опубликован → архив. Переходы — только через сервис (`documents/workflow.go`), в одной транзакции
с записью статуса, снимком истории (`kind=status`, хранится всегда), событием рецензии (`review_events`), событием журнала (`audit_events`)
и снятием замка. Миграция `0007_review.sql`: `review_comments`, `review_events`.

| Действие | Кто | Условия |
|---|---|---|
| `POST …/submit` `{base_revision}` | владелец с правом писать, Директорат | статус «черновик»; редакция та, что видел автор; **линтер без ошибок** |
| `POST …/withdraw` `{comment?}` | владелец, Директорат | статус «на проверке» (Редактор забирать чужое не вправе — для него «вернуть») |
| `POST …/verdict` `{verdict, comment, base_revision}` | Редактор (право `review`), Директорат | «на проверке»; **не свой документ** (Директорат — любой); редакция та, что читал рецензент |
| `POST …/archive`, `…/unarchive` `{comment?}` | Редактор (право `edit_published`), Директорат | published ↔ archived |

- **Вердикты.** `approve` — принять **и опубликовать** (состояния «принято, но не опубликовано» нет): повторный линтер, объекту без шифра
  присваивается следующий О-№ (под `pg_advisory_xact_lock`, параллельные публикации не повторяют номер — тест с шестью горутинами),
  ставится `published_at`. `return` — снова черновик автора; `reject` — в архив. У `return` и `reject` **причина обязательна**
  (и в коде, и ограничением БД). Причина и весь ход видны автору (`GET …/review`).
- **Права считает сервер:** `TeamDocument.workflow` (`submit`, `withdraw`, `review`, `comment`, `archive`, `unarchive`); интерфейс их только показывает.
  Ошибки: `403 self_review` (свой документ), `403 forbidden`, `404` (документа человек не видит), `409 invalid_state` (не тот статус),
  `409 conflict` + `current_revision`, `409 locked` (документ правит другой), `422 lint_failed` + отчёт `lint`.
- **Возвращённый документ — снова личный черновик автора:** Редактор чужой черновик не видит (правило прежнее), поэтому вердикт «вернуть»
  возвращает ответ рецензенту, но открыть документ он уже не сможет.
- **Комментарии** (`POST …/comments`, `PUT/DELETE …/comments/:cid`): к блоку (по его `id`) или к документу целиком; пишет тот, кто выносит вердикт,
  пока документ на проверке; «исправлено» отмечает рецензент и автор; удаляет автор комментария и Директорат. Блок могут удалить — комментарий остаётся
  («блок удалён»). Удаление аккаунта обезличивает автора комментария и событий (`ON DELETE SET NULL`), текст остаётся.
- **Линтер канона** (`documents/lint.go`, `GET …/lint`): *ошибки* (не пропускают отправку и принятие): нет блоков, ссылка на несуществующий
  документ; *предупреждения*: ссылка на неопубликованный документ или на самого себя, у объекта нет шапки досье, неизвестный отдел, одинаковые блоки
  подряд. Уникальность шифра и О-№ обеспечивают уникальные индексы БД, а номер присваивается при публикации — «дублей номеров» линтер не ищет.
- **Интерфейс:** `WorkflowBar` над вкладками (кнопки по `workflow`, окно вердикта), вкладка «Рецензия» (`ReviewPanel`: проверка канона, комментарии, ход)
  со счётчиком открытых комментариев; отправка недоступна, пока есть несохранённые правки (на проверку уходит сохранённая редакция).

### Рабочий стол, шаблоны, глоссарий, экспорт и импорт (шаг 3.6)

Всё — в панели команды (`team_panel`), права считает сервис документов по человеку; интерфейс их только показывает. Статистики просмотров
здесь нет — она в этапе 4.

- **Рабочий стол** (`/team`, `GET /api/team/dashboard`, `documents/dashboard.go`): мои документы по состояниям (счётчики и последние),
  **возвращённые на доработку** — с причиной и открытыми замечаниями рецензента, ждущие проверки, а рецензентам (право `review`) — очередь
  на проверку (20 старейших, `queue_total` — сколько всего; свои документы в очередь не входят). «Роли и права» переехали на `/team/roles`.
- **Шаблоны** (миграция `0008_templates.sql`, `documents/templates.go`, `/api/team/templates`, раздел «Шаблоны»): два вида — *шаблон документа*
  (тип, название, допуск, гриф, блоки) и *набор блоков* (вставляется в открытый документ). Читают все члены команды; заводят, правят и удаляют
  с правом `manage_templates` (Редактор, Архивариус, Директорат). Содержимое проверяется **так же строго, как документ** (`normalizeBlocksAt`):
  шаблон, который нельзя вставить, не сохранится. Имя уникально среди шаблонов своего вида без учёта регистра и пробелов (`409 name_taken`, поле `name`).
  «Сохранить как шаблон» — в панели документа (берёт то, что в редакторе, с несохранёнными правками), «Создать по шаблону» —
  `/team/documents/new?template=<id>`, набор — список «Набор блоков» на панели редактора (`insertBlocks`: у вставленных блоков **новые id**,
  вторая шапка досье пропускается).
- **Глоссарий** (миграция `0009_glossary.sql`, `documents/glossary.go`, `/api/team/glossary`, раздел «Глоссарий»): термин, определение
  (до 2000 знаков), до 10 других написаний (`jsonb`: пакета `lib/pq` в проекте нет). Поиск `?q=` — по термину, написаниям и определению без учёта
  регистра, запрос живёт в адресе. Читают все члены команды; ведёт право `manage_glossary` (Редактор, Архивариус, Директорат). Термин уникален
  без учёта регистра и пробелов (`409 name_taken`, поле `term`); написание, совпавшее с самим термином, и повторы убираются.
  Создание, правка и удаление шаблонов и терминов пишутся в журнал аудита (`template.*`, `glossary.*`).
- **Экспорт** (`GET /api/team/documents/:id/export?format=json|md`, `documents/exchange.go`): файл для скачивания (`Content-Disposition:
  attachment; filename="<адрес>.json"`; у объекта без шифра — `object-<id>`). Доступ — как к чтению документа в панели: чужой черновик — `404`.
  Отдаётся **сохранённая** версия целиком, без фильтрации по допуску (как в редакторе), с уровнями блоков и фрагментов. *JSON* — формат загрузки
  (`docs/documents.md`), круг «скачать → править → загрузить» работает. *Markdown* — для чтения и правки текста вне архива: сведения о документе
  в шапке, блоки как Markdown, закрытые блоки — комментарием `<!-- допуск блока: N -->`, закрытые фрагменты — `[текст]{допуск=N}`. Обратно Markdown
  не загружается. Тест обходит все 15 видов блоков (новый вид без отрисовки роняет тест).
- **Загрузка из файла** (`POST /api/team/documents/import[?dry_run=1]`, тело — сам файл; кнопка «Загрузить из файла» в «Документах»): один документ
  (пакет отклоняется), разбор строгий — неизвестные поля и опечатки в именах полей называются по имени. Нужно право писать. **Всегда создаётся
  черновик за загрузившим**: статус из файла не берётся (`status_ignored` сообщает об этом), так что загрузка не обходит рецензию — в отличие от
  команды `kupol doc import`, которую запускает администратор на сервере. Шифр из файла сохраняется (занят — `409 code_taken`); у объекта без шифра
  номер присвоится при публикации. `dry_run=1` проверяет, ничего не создавая, — интерфейс сначала показывает итог (название, тип, шифр, число
  блоков) или список замечаний с путями (`blocks[3].data.text`), и только потом создаёт. Размер — как у любого запроса (1 МиБ, предел PHP-прокси).

### Поиск (шаг 4.1)

`GET /api/search?q=…&type=&class=&department=&category=&containment=&year_from=&year_to=&status=&page=&per_page=` (гость тоже; `status` — только
Директорату; ответ `no-store`). Код — `documents/search.go` (запрос) и `documents/search_index.go` (индекс), миграция `0011_search.sql`, экран `/search`
(`SearchView.vue`, строка `SearchBox.vue` — на странице поиска, в каталоге и в меню).

- **Закрытого в выдаче не существует** (главное правило этапа 2 распространяется на поиск). Индекс `document_search` хранит текст блока **по уровням
  фрагментов**: у абзаца с закрытым фрагментом — две строки (открытая часть и закрытая, каждая со своим уровнем). Читатель уровня L ищет только по
  строкам ≤ L и только среди документов ≤ L (а неопубликованное — только Директорат); сниппеты, счётчик «Найдено» и страницы считаются по тем же условиям,
  поэтому слово из закрытого фрагмента не находит документ, не попадает в выдержку и не меняет число найденных. Статус и уровень **самого документа**
  берутся из `documents` при запросе (публикация, архив и смена допуска индекс не трогают).
- **Что индексируется** — явный список по видам блоков (`blockPieces`); ссылки `doc_link` **не индексируются** (шифр и примечание видны читателю, только если
  цель ему доступна — в индексе этого не проверить), шапка досье, разделитель и страница — без текста. Новый вид блока, не занесённый ни в список
  извлечения, ни в `searchExcluded`, роняет тест. Кроме блоков в индекс идут название (вместе с шифром) и место обнаружения объекта.
- **Слова.** `websearch_to_tsquery('russian', …)`: слова, «фраза в кавычках», `-исключение`, `or`; русская морфология (`сотрудник` находит `сотрудников`).
  Слова запроса ищутся **в одном месте** — в названии или в одном блоке; `-слово` исключает блок, а не весь документ. Шифр в любой раскладке
  (`о-41`, `O-041`) находит документ первым (кроме закрытого). Запрос из одних частых слов — `ignored: true` (не «ничего не найдено»).
- **Регистр считает сервер**, а не база: в индекс идёт строчная копия (`norm`), tsvector строится из неё, запрос тоже понижается в Go. База с локалью `C`
  (так устроены тестовые и CI-базы) не понижает кириллицу — без этого «Сотрудники» не находились бы по «сотрудник». Сниппет берётся из строчной копии, а
  регистр возвращается по исходному тексту (`snippetParts`; позиции совпадают, потому что `unicode.ToLower` не меняет число знаков). В сниппете нет
  разметки — куски `{text, match}`, подсветку рисует интерфейс `<mark>`.
- **Выдача.** По документу — до 3 лучших выдержек (название 1.0 > досье 0.4 > текст 0.1 по весу), порядок — по совпадению, затем шифр. Выдержка из блока — ссылка
  `/doc/О-041#b-<id блока>`: страница документа прокручивается к блоку, отмечает его (`data-found`) и ставит на него фокус; блока нет (закрыт читателю) — фокус на названии.
- **Сопровождение индекса** — в той же транзакции, что и запись документа: загрузка (`Import`), создание и сохранение в редакторе (в том числе откат версии),
  публикация (присвоенный шифр входит в строку названия); удаление — каскадом. При старте `EnsureSearchIndex` перестраивает индекс, если версия правил
  (`searchIndexVersion`, таблица `document_search_state`) не совпала: так индекс появляется у документов, существовавших до поиска, и обновляется при смене
  правил. `kupol doc reindex` — принудительно.
- **Тесты.** Матрица «читатель 0–7 × метка каждого уровня в блоке и во фрагменте» на уровне сервиса и на уровне HTTP-ответа (ни метки, ни названия закрытого
  документа, ни черновика в теле), морфология и сниппеты, шифры, фильтры и страницы, сопровождение индекса при каждой записи, перестройка. Мутации (нет фильтра
  по уровню строки, по уровню документа, по статусу; все фрагменты в одной строке) ловятся. `e2e/search.spec.js` (6): гость, читатели уровней 4 и 5, Директорат,
  фильтры в адресе, переход к блоку, телефон 375 px и axe.
- **Известные ограничения:** фраза из слов до и после закрытого фрагмента находит абзац (для читателя между ними полоса зачернения); поиск без опечаток
  и подсказок — это этап позже.

### «Упоминается в» и «Картотека» (шаг 4.2)

- **Обратные ссылки** — таблица `document_links` (миграция `0012_links.sql`): по строке на пару «блок `doc_link`, цель». Цель хранится **шифром**, а не номером:
  ссылка на документ, которого ещё нет, начинает работать, когда он появится. Строки строит тот же код, что и индекс поиска (`reindexDocument`,
  `search_index.go`), в той же транзакции — загрузка, создание, сохранение, публикация; удаление документа — каскадом. Ссылка документа на самого себя не
  считается; несколько ссылок из одного документа на одну цель — одно упоминание. Версия производных данных (`searchIndexVersion` = 2) перестраивает и
  связи при старте, если их ещё не было.
- **Кто что видит** (`documents/mentions.go`, поле `mentioned_in` в `GET /api/documents/:шифр`): упоминание попадает в ответ, только если читатель вправе
  видеть **и** документ-источник (допуск, опубликованность — как в каталоге), **и** сам блок-ссылку (его уровень не выше допуска). Иначе по списку можно
  было бы узнать, что закрытый документ существует и на что-то ссылается. Источник без шифра (черновик объекта) в список не идёт: ссылаться на него нечем.
  Порядок — естественный по шифру (О-9 раньше О-10), не больше 100. В предпросмотре команды поле не заполняется.
  Тесты: матрица «источник × уровень документа × уровень блока × статус × читатель 0–7» и сопровождение при каждой записи; мутации (нет фильтра по уровню блока,

### Граф связей — «доска с нитками» (шаг 4.3)

`GET /api/graph/:шифр?depth=1|2` (гость тоже, `no-store`), экран `/graph/:шифр` (`GraphView.vue`; ссылка «Связи документа» — внизу листа документа).
Строится по `document_links` (`documents/graph.go`): документ в центре, ссылки в обе стороны, при `depth=2` — «через одного»; не больше 40 карточек (обрезка
по естественному порядку шифров, `truncated: true`).

- **Что видно.** Карточка — если читатель вправе открыть документ (допуск, опубликованность); нить — если видны **оба конца и сам блок-ссылка** (уровень блока не
  выше допуска). Закрытое не появляется даже как безымянная карточка или оборванная нить. Закрытый и несуществующий центр — одинаково `404`. Тесты: матрица «читатель
  0–7 × документы разных уровней × блоки-ссылки × черновик × глубина», мутации (нет проверки уровня блока, уровня цели, статуса) ловятся; HTTP; `e2e/graph.spec.js` (5).
- **Раскладка** — чистая функция (`lib/graph.ts`, `tests/graph.test.ts`): центр, вокруг эллипсом — прямые связи, дальше — «через одного» по углам родителей; карточки
  не перекрываются при любом числе связей до предела (проверено), нити провисают вниз и изгибаются вбок детерминированно (по шифрам), наклон карточки — от шифра.
- **Доступность.** Карточка — ссылка (`<a>` в SVG, Tab и Enter; у центра `aria-current`), её название читает скринридер целиком; тот же граф **списком** (документы и
  ссылки) под доской — для тех, кому доска неудобна. Доска прокручивается внутри своей области, страница не ползёт на 375 px.

### Подпись PHP-прокси

PHP-прокси на shared-хостинге ставит реальный IP клиента и подписывает запрос общим секретом; Go доверяет IP из заголовка
только при валидной подписи.

```
X-Kupol-Client-Ip: <IP клиента>
X-Kupol-Timestamp: <unix-время, сек; допуск ±60 с>
X-Kupol-Signature: hex(HMAC-SHA256(secret, "KUPOL-PROXY-V1\n" + ts + "\n" + ip + "\n" + МЕТОД + "\n" + сырой_URI))
```

- Нет заголовков — запрос напрямую (WebSocket, загрузки): IP из соединения, `X-Forwarded-For` только от `KUPOL_TRUSTED_PROXIES`.
- Заголовки есть, но подпись неверна или просрочена — `401 bad_proxy_signature` (громко: иначе при рассинхроне часов или
  секрета все пользователи слились бы в один IP).
- Сырой URI входит в подпись, поэтому **ни один узел между PHP и Go не должен переписывать путь** (проверено для nginx).
- Формат — в `backend/internal/proxyauth` и `frontend/public/api/lib.php`; общий эталонный вектор проверяется тестами обеих сторон.

## PHP-прокси

Совместим с PHP 8.3. Настройки — `api/config.php` рядом с `index.php` (образец `config.example.php`) или переменные `KUPOL_PROXY_*`
(dev). Пересылает `Cookie`, `Authorization`, `Origin`, `Content-Type` и другие из белого списка; `Set-Cookie` от Go доходит
раздельно; тело ответа идёт потоком; таймауты — 502/504 в формате API; версия PHP не светится. Боевой `config.php` в git и в сборку
не попадает.

Каждый ответ несёт `Server-Timing: proxy;dur=…, upstream;dur=…` — сколько ушло на PHP и сколько на Go API до первого байта
(вкладка «Сеть» браузера): сразу видно, где медленно — хостинг, дорога до VPS или сам API.

Пустая строка запроса («`/api/x?`») нормализуется до подписи (`normalize_request_uri`): Apache отдаёт PHP `REQUEST_URI` с
хвостовым «?», а curl уходит без него, и подпись иначе не совпала бы с тем, что видит Go (401 `bad_proxy_signature`). Проверяет это
`deploy/check-site.sh` на настоящем хостинге; на `php -S` дефект не воспроизводится, поэтому отдельно есть тест чистой функции.

### Правила

- **Токены.** Компоненты используют смысловые токены (`--text`, `--surface`, `--accent`…), а не палитру; значения — только в
  `src/styles/tokens.css`. `tests/tokens.test.ts` читает этот файл и проверяет контраст каждой пары: текст ≥ 4.5:1, границы полей
  и двойное кольцо фокуса ≥ 3:1. Правка палитры, ломающая читаемость, роняет тест.
- **Дизайн.** Тёмный стол (`--bg`, текстура `desk.svg`) и светлые листы бумаги (`UiSheet`, текстура `paper.svg`). Интерфейс — PT Sans,
  заголовки и штампы — Oswald, документы — IBM Plex Mono («машинка»; Courier Prime кириллицы не имеет). Штампы и зачернения —
  с неровным краем (маска `ink.svg`). Шрифты — свои файлы (`@fontsource`), лицензия OFL-1.1.
- **Данные.** Списки, каталог, справочники, документы — `useQuery` (ключи в `api/query.ts`). Рабочая копия редактируемого документа
  (`TeamDocumentView`) — локальное состояние, потому что это черновик поверх серверных данных. Состояние списков (фильтры,
  сортировка, страница) живёт в адресе; `useQueryFilters` собирает быстрые подряд изменения, не теряя их.
- **Права.** Интерфейс ничего не выводит из ролей: `auth.can('...')` смотрит на список прав от сервера. Без права страница
  показывает «Дело не найдено» по тому же адресу; перед проверкой охрана страниц перечитывает сессию.
- **Документы.** Ответ сервера уже отфильтрован по допуску: закрытое приходит метками `redacted` с одним лишь уровнем, интерфейс
  ничего не скрывает сам (`RedactedPlate` — блок, `RichRuns` — фрагмент). Шапка досье берёт свойства документа из контекста
  (`components/document/context.ts`).
- **Меню и вход.** Формы входа на главной нет: бургер (`#menu-toggle`) открывает боковое меню `AppMenu`, из него — окно входа
  `AuthModal` (вкладки «Вход» и «Регистрация»; всегда открывается на «Входе»). Общее поведение окон — `ui/overlay.ts`: фокус
  внутри и по кругу на Tab, Esc закрывает, страница под окном получает `inert` и не прокручивается (`html.scroll-locked`), фокус
  возвращается на открывший элемент (или на бургер). Гостя, которого охрана вернула на главную с `?next=`, встречает окно входа.
- **Формы.** `useForm` (ошибки по полям, общая ошибка, защита от двойной отправки), `UiField` связывает подпись, подсказку и ошибку
  с полем (`aria-invalid`, `aria-describedby`). Переход после успешной отправки делает сама форма: после входа главная
  перерисовывается и размонтирует форму, а Vue не доставляет события размонтированных компонентов.
- **Навигация по страницам.** `RouterLink` сравнивает только путь, а не query, поэтому у ссылок пагинации и разделов панели команды
  `aria-current` управляется вручную.
- **Типы.** Формы ответов не пишутся руками: сменили Go-структуру — `make types`. Ключ `staff` в API — `1`, а не `true` (так
  ловятся расхождения, которые типы не видят: значения query-параметров проверяют e2e).
- Сборка (`npm run build`) сначала проверяет типы, затем удаляет из `dist` боевые файлы прокси (`api/config.php`,
  `config.example.php`).

### Редактор (шаг 3.3)

WYSIWYG на Tiptap 3 (ProseMirror). Редактор — только **представление**: серверный формат блоков (`{id, type, level, data}`, текст
«фрагментами» `{text, level, bold, italic}`) остаётся единственной моделью, проверка и фильтрация по допуску — на сервере.
Грузится отдельным куском (≈ 425 КБ, 128 КБ сжатого) только на странице документа команды.

| Файл | Что |
|---|---|
| `src/editor/convert.ts` | чистое преобразование блоки ⇄ дерево редактора: каноническая форма (как хранит сервер), склейка фрагментов, блок неизвестного вида хранится «коробкой» без изменений |
| `src/editor/schema.ts` | узлы для 15 видов блоков, метка `redact` («закрыть до уровня N»), общие атрибуты `blockId` и `level`; идентификаторы блоков всегда уникальны и подходят под правила сервера |
| `src/editor/fields.ts` | перечень полей шапки каждого блока (номер, дата, вид, наклон…) и подписи — по нему строятся представления и тесты |
| `src/editor/commands.ts`, `keys.ts` | вставка, перемещение, удаление, допуск блока, закрытие фрагмента, состояние для панели; Enter/Backspace в списках, цитатах, ячейках |
| `src/editor/problems.ts` | подсветка блоков, к которым у сервера есть замечания (`blocks[3].data.text` → блок 4) |
| `components/editor/` | `BlockEditor` (сборка), `EditorToolbar`, представления узлов `BlockNodeView`/`TableNodeView`, поля `BlockFields`/`LinesField`; стили — `styles/editor.css` |

Что важно помнить:

- **Нет ложных правок.** Обратное преобразование выдаёт ту же каноническую форму, что хранит сервер; `TeamDocumentView` перед сравнением
  приводит сохранённое содержимое к ней же (`canonicalContent`). Открыть документ и ничего не тронуть — не изменение (e2e это проверяет).
- **Пустое не отправляется.** Пустые абзацы, пункты списка, абзацы бланка и вырезки в данные не попадают (сервер отклонил бы их как
  «пустые»); в редакторе они остаются, пока автор не начнёт писать. Пустые обязательные поля сервер отмечает сам, блок подсвечивается,
  а в списке замечаний есть ссылка «Блок 4 — Штамп».
- **Пересоздание вместо подмены.** Редактор читает содержимое один раз; отмена правок, черновик и восстановление версии пересоздают его
  по `:key` (нет лишней истории отмены и гонок). После обычного «Сохранить» редактор не пересоздаётся, если сервер вернул то же самое.
- **Выделение блока целиком** (`NodeSelection`) не заменяется набранным текстом: редактор узнаёт о выделении браузера с задержкой в
  десятки миллисекунд, и первая клавиша иначе уничтожила бы блок (так шапка досье пропадала в тестах). В e2e перед клавишами ждут,
  пока выделение дойдёт до редактора (`clickIn`, `selectStart`).
- **Изолированные блоки** (`isolating`): Backspace на границе не сливает соседние блоки; удаляют их кнопкой панели. Перенос строки в
  цитате, сноске и ячейке — собственная команда `insertLineBreak` (встроенная `setHardBreak` в таких узлах отказывает).
- **Таблица** — прямоугольная, первая строка — названия столбцов (простой текст), её удалить нельзя; объединения ячеек нет.
- **Клавиши:** Enter — новый абзац/пункт, Shift+Enter — перенос строки, Ctrl+B / Ctrl+I, Ctrl+Z / Ctrl+Shift+Z, Ctrl+S — сохранить,
  Alt+F10 — на панель инструментов, Escape на панели — обратно в текст.
