# КУПОЛ — разработка

Схема запроса (в dev идёт тем же путём, что на проде):

```
браузер ──► Vite (dev) / Apache (прод) ──► PHP-прокси ──► Go API ──► PostgreSQL
                     kupol.vladinc.ru            api.kupol.vladinc.ru (nginx на VPS)
```

Прямо на api-поддомен из браузера ходят только WebSocket, загрузки файлов и раздача `uploads/` (этапы 5–6);
все обычные запросы идут через PHP-прокси (`/api/...`).

## Что нужно

Go 1.27+, Node 24+, PHP 8.3+ (CLI, с cURL), Docker (PostgreSQL и проверки инфраструктуры), `jq`, `curl`.
Для `make test-infra` ещё `lftp` и `sshd`; для браузерных тестов — Chromium (`npx playwright install chromium`).

## Быстрый старт

```bash
make env      # создать .env (секрет прокси генерируется)
make dev      # всё сразу; сайт на http://127.0.0.1:5173, Ctrl+C останавливает
```

`make help` — список всех команд.

| `KUPOL_LIMIT_LOGIN_ATTEMPTS` | неудачных входов на пару IP+логин за 15 мин (по умолчанию 5) |
| `KUPOL_LIMIT_LOGIN_LOCK_ATTEMPTS` | неудачных входов на один логин с любых IP за 15 мин (15) |
| `KUPOL_LIMIT_REGISTER_PER_HOUR` | регистраций с одного IP в час (3) |

В `.env.example` лимиты регистрации и API смягчены, чтобы сквозные тесты могли создавать много пользователей с одного IP. В проде
их задавать не нужно: действуют значения из спецификации. Позже они переедут в настройки админки (этап 7).

## Go API

- `kupol serve` — запуск (сам применяет миграции), `kupol migrate up|down|status`, `kupol user ...`, `kupol doc ...`, `kupol version`.
- Новая миграция — файл `backend/internal/database/migrations/NNNN_название.sql` с `-- +goose Up` / `-- +goose Down`.
- Формат ошибок: `{"error":{"code":"...","message":"...","request_id":"...","fields":{...},"retry_after":N}}`.
  Фронтенд ориентируется на `code`; `fields` — ошибки по полям формы, `retry_after` (секунды) — для 429.
- `GET /health` (напрямую, для мониторинга) и `GET /api/health` (через прокси): статус и связь с БД; 503, если БД недоступна.
- Режим обслуживания (этап 7) должен отвечать `503` с кодом `maintenance` — фронтенд по нему показывает «Архив закрыт на инвентаризацию».

### Аккаунты и сессии (этап 1)

| Метод и путь | Что делает | Ответ |
|---|---|---|
| `GET /api/auth/session` | кто я; для гостя `{"user": null}` (не 401, чтобы не сорить ошибками в консоли) | 200 |
| `GET /api/auth/captcha` | вопрос анкеты для регистрации `{id, question}`, ответ принимается один раз, 10 минут | 200 |
| `POST /api/auth/register` | `{login, password, captcha_id, captcha_answer}` → аккаунт, вход, кука; **резервный код показывается один раз** | 201 `{user, backup_code}` |
| `POST /api/auth/login` | `{login, password}` → кука | 200 `{user}` / 401 `invalid_credentials` / 429 |
| `POST /api/auth/logout` | завершает текущую сессию (идемпотентно) | 204 |
| `POST /api/auth/restore` | `{login, backup_code, new_password}` → новый пароль, **новый** резервный код, все прежние сессии завершены | 200 `{user, backup_code}` |
| `POST /api/me/password` | `{current_password, new_password}`; остальные сессии завершаются, текущая остаётся | 204 |
| `DELETE /api/me` | `{password}` — «сдать дело в архив»: полное удаление аккаунта | 204 |

Как это устроено:

- **Сессии** — серверные, в PostgreSQL. В куке `kupol_session` лежит случайный токен (32 байта), в БД — только его SHA-256.
  Кука `HttpOnly`, `SameSite=Lax`, `Path=/`, без `Domain` (только `kupol.vladinc.ru`), `Secure` — в prod. Срок скользящий 30 дней
  (продлевается при активности не чаще раза в 5 минут), но не дольше 90 дней от входа. Удаление строки завершает сессию мгновенно.
- **Пароли** — argon2id (19 МиБ, 2 прохода) в PHC-формате: параметры можно усиливать, старые хеши пересчитываются при входе.
  Перед хешированием пароль нормализуется NFKC. Число одновременных хешей ограничено (память общего VPS). Для несуществующего
  логина считается «холостой» хеш: по времени ответа логин не угадать.
- **Логин** — 3–24 символа, латиница или кириллица (не вперемешку: иначе можно подделать «Kуратор» с латинской K), цифры, `_`, `-`;
  уникален без учёта регистра; есть список зарезервированных слов. Правила проверяются и на сервере (`accounts/rules.go`), и на
  клиенте (`src/lib/rules.js`) по **общему файлу векторов** `backend/internal/accounts/testdata/login_rules.json`.
- **Резервный код** — `KUPOL-XXXX-XXXX-XXXX-XXXX` (80 бит), в БД только argon2id-хеш; при восстановлении заменяется новым.
- **Анкета вместо капчи** — вопрос по вселенной (ответ читается на главной странице). Вопрос одноразовый: неверный ответ его гасит.
  Банк вопросов — `accounts/captcha.go`; при изменении текста главной проверьте, что вопросы остаются отвечаемыми.
- **Лимиты** (спецификация §2): вход — 5 неудач на IP+логин и 15 на логин с любых IP за 15 минут, после чего вход блокируется
  даже с верным паролем; регистрация — 3 в час на IP; API — 120 запросов в минуту на пользователя (гость — на IP); перед сессией
  действует грубый лимит по IP в 10 раз выше. Смена пароля, удаление и восстановление считаются теми же счётчиками, что и вход
  (украденной сессией пароль не перебрать). Счётчики в памяти процесса. Ответ 429 несёт `Retry-After`.
- **CSRF** — изменяющие запросы (POST/PUT/PATCH/DELETE) принимаются только с `Origin` = `KUPOL_SITE_ORIGIN`; без `Origin` — только
  если нет куки сессии (curl, скрипты). Тело — строго `application/json`, до 16 КиБ, неизвестные поля отвергаются.
- **Админ-команды** (Директорат и уровни 4–6 выдаются только здесь до появления админки):

  ```bash
  kupol user show <логин>
  kupol user set-level <логин> <1-6>
  kupol user set-directorate <логин> on|off
  kupol user set-role <логин> <author|editor|moderator|archivist> on|off   # роли команды (этап 3)
  kupol user reset-password <логин>      # выводит временный пароль, завершает все сессии
  ```

  На VPS: `sudo kupol-admin user ...` (`deploy/server/kupol-admin.sh`).
- Фоновая уборка: просроченные сессии и вопросы анкеты — раз в час, ключи ограничителя — раз в минуту.
- Отложено до своих этапов: шкала XP в «пропуске» (нужны пороги из админки), TOTP для персонала (роли — этап 3), смена логина
  через заявку (этап 7), грамоты и закладки в личном деле (этап 4).

### Роли и права команды (этап 3)

Роли — Автор, Редактор, Модератор, Архивариус; у человека их может быть несколько (таблица `user_roles`, миграция 0004).
Директорат — не роль, а флаг пользователя: он подразумевает все роли и все права и выдаётся только командой на сервере.

- **Права выводит сервер.** `accounts/roles.go` хранит таблицу «роль → права» (`User.Can`); в ответах `/api/auth/session`, входа и
  регистрации у пользователя есть `roles` и готовый список `capabilities`. Интерфейс ничего из ролей не выводит (`auth.can('...')`).
  Права читаются из БД на каждый запрос, поэтому выданная или снятая роль действует сразу, на открытой сессии.
- **Кто что может** (тест `TestRoleCapabilitiesMatrix` держит таблицу отдельно от кода):

  | Право | Автор | Редактор | Модератор | Архивариус | Директорат |
  |---|:-:|:-:|:-:|:-:|:-:|
  | `team_panel` — войти в панель команды | ✓ | ✓ | ✓ | ✓ | ✓ |
  | `write_drafts` — создавать и править черновики | ✓ | ✓ | | | ✓ |
  | `review` — проверять, выносить вердикт | | ✓ | | | ✓ |
  | `publish` — публиковать (не свои) | | ✓ | | | ✓ |
  | `edit_published` — править опубликованное на месте | | ✓ | | | ✓ |
  | `manage_glossary`, `manage_templates` | | ✓ | | ✓ | ✓ |
  | `manage_team` — выдавать и снимать роли | | | | | ✓ |

- **API:** `GET /api/team/roles` (нужно `team_panel`), `GET /api/team/members?q=&role=&staff=1&page=&per_page=`,
  `PUT`/`DELETE /api/team/members/:login/roles/:role` (нужно `manage_team`; повтор безопасен, в ответе `changed`). Гражданину — 401,
  вошедшему без права — 403 `forbidden`; изменяющие запросы защищены проверкой Origin, как и остальные.
- **Интерфейс:** `/team` — «Роли и права» (ваши роли, ваши права, таблица «что даёт роль»); `/team/members` — экран «Команда» для
  Директората: поиск по части логина, фильтры «роль» и «только команда», кнопки-переключатели ролей. Без права страница
  показывает «Дело не найдено» по тому же адресу; охрана страниц перед этим перечитывает сессию (роль могли снять, а человек мог
  выйти в другой вкладке). Роли видны в личном деле; в боковом меню есть пункт «Панель команды».
- **CLI:** `kupol user set-role` (на VPS `sudo kupol-admin user set-role ...`); `kupol user show` показывает роли.
- Пока не сделано в этапе 3: сами документы в team panel (черновики, редактор, проверка) — шаги 3.2–3.7.

### Документы (этап 2)

Модель, формат JSON-файла, типы блоков, правила уровней допуска, команды `kupol doc ...` (загрузка до появления редактора) и
API чтения (`/api/documents`, `/summary`, `/recent`, `/:шифр`) описаны в **`docs/documents.md`**. Кратко:

- Закрытое от читателя **не попадает в ответ**: документ собирается заново из белого списка полей; закрытые блоки и фрагменты
  становятся метками `redacted` с одним лишь уровнем. Проверяется свойство-тестом (метка секрета на каждом поле каждого типа
  блока × уровни 0–7).
- Уровень 7 — только Директорат; Директорат видит всё, включая черновики. Неопубликованное для остальных — всегда 404.
- Миграция `0003_documents.sql` создаёт коллацию `kupol_natural` (ICU, естественная сортировка шифров: `О-9` раньше `О-10`),
  таблицы `documents` и `document_reads`. PostgreSQL должен быть собран с ICU (в docker-образе Postgres 17 — есть; на VPS проверить
  `SELECT collprovider FROM pg_collation` при первой миграции).
- Пока нет редактора (этап 3), документы загружает автор: `kupol doc import файл.json` (`sudo kupol-admin doc import …` на VPS).

### Подпись PHP-прокси

PHP-прокси на shared-хостинге ставит реальный IP клиента и подписывает запрос общим секретом; Go доверяет IP из заголовка
только при валидной подписи.

```
X-Kupol-Client-Ip: <IP клиента>
X-Kupol-Timestamp: <unix-время, сек; допуск ±60 с>
X-Kupol-Signature: hex(HMAC-SHA256(secret, "KUPOL-PROXY-V1\n" + ts + "\n" + ip + "\n" + МЕТОД + "\n" + сырой_URI))
```

- Нет заголовков — запрос напрямую (WebSocket, загрузки): IP из соединения, `X-Forwarded-For` только от `KUPOL_TRUSTED_PROXIES`.
- Заголовки есть, но подпись неверна или просрочена — `401 bad_proxy_signature` (громко: иначе при рассинхроне часов или
  секрета все пользователи слились бы в один IP).
- Сырой URI входит в подпись, поэтому **ни один узел между PHP и Go не должен переписывать путь** (проверено для nginx).
- Формат — в `backend/internal/proxyauth` и `frontend/public/api/lib.php`; общий эталонный вектор проверяется тестами обеих сторон.

## PHP-прокси

Совместим с PHP 8.3. Настройки — `api/config.php` рядом с `index.php` (образец `config.example.php`) или переменные `KUPOL_PROXY_*`
(dev). Пересылает `Cookie`, `Authorization`, `Origin`, `Content-Type` и другие из белого списка; `Set-Cookie` от Go доходит
раздельно; тело ответа идёт потоком; таймауты — 502/504 в формате API; версия PHP не светится. Боевой `config.php` в git и в сборку
не попадает.

Пустая строка запроса («`/api/x?`») нормализуется до подписи (`normalize_request_uri`): Apache отдаёт PHP `REQUEST_URI` с
хвостовым «?», а curl уходит без него, и подпись иначе не совпала бы с тем, что видит Go (401 `bad_proxy_signature`). Проверяет это
`deploy/check-site.sh` на настоящем хостинге; на `php -S` дефект не воспроизводится, поэтому отдельно есть тест чистой функции.

## Фронтенд

- Клиент API — `src/api/client.js`: единый `ApiError` (`code`, `fields`, `retryAfter`), таймаут, подписка на исходы запросов.
- `src/stores/connection.js` — состояние связи с архивом; сбой (0/502/503/504) закрывает страницы с `meta.needsApi`,
  режим обслуживания закрывает весь сайт.
- `src/stores/auth.js` — вошедший пользователь, вход/регистрация/выход/восстановление/смена пароля/удаление. Резервный код хранится
  только в памяти и стирается после подтверждения.
- Роутер (`src/router/index.js`): `requiresAuth` — только вошедшим (гостя ведут на главную, после входа возвращают обратно;
  путь возврата проверяется `safeNextPath` от открытых перенаправлений), `guestOnly` — только гостям.
- Документы: `DocumentView` (`/doc/:ref`) рисует блоки через `BlockRenderer` (по одному компоненту на тип, `components/blocks/`);
  закрытое — `RedactedPlate` (блок) и `RichText` (фрагмент). Ответ сервера уже отфильтрован, интерфейс ничего не скрывает сам.
  Каталог — `CatalogView` (`/catalog`); состояние (фильтры, сортировка, страница, вид) живёт в адресе, логика — `src/lib/catalog.js`.
  `RouterLink` сравнивает только путь, а не query, поэтому у ссылок навигации по страницам `aria-current` выключен вручную.
- Меню и вход: формы входа на главной нет. В шапке — бургер (`#menu-toggle`), он открывает боковое меню `SideMenu`
  (Главная, Каталог, Личное дело для вошедшего; для гостя — кнопка «Войти или зарегистрироваться»), а та — окно входа
  `AuthModal` с вкладками «Вход» и «Регистрация» (`AuthPanel`). Что открыто, хранит `stores/ui.js`; общее поведение окон —
  `composables/useOverlay.js`: фокус внутри и по кругу на Tab, Esc закрывает, страница под окном получает `inert` и не
  прокручивается (`html.scroll-locked`), фокус возвращается на открывший элемент (или на бургер). Любой переход закрывает
  окна; завершение первой загрузки страницы — не переход. Гостя, которого охрана вернула на главную с `?next=` (например,
  со страницы `/file`), встречает окно входа, а после входа он попадает туда, куда шёл. Из «Доступ запрещён» окно
  открывается кнопкой, и вход возвращает на тот же документ (страница документа перечитывается при входе и выходе, потому что
  от допуска зависит, что закрыто). Каталог в шапке отдельной ссылки не имеет — он в меню.
- Формы: `useForm` (ошибки по полям, общая ошибка, защита от двойной отправки, фокус на первом поле с ошибкой), `FormField`
  (подписи, `aria-invalid`, `aria-describedby`, показать/скрыть пароль). Скринридеры получают ошибки через `role="alert"`.
- Переход после успешной отправки формы делает сама форма, а не событие родителю: как только в хранилище появляется пользователь,
  главная перерисовывается и размонтирует форму, а Vue не доставляет события размонтированных компонентов.
- Шрифты — свои файлы (`@fontsource`): PT Mono (текст) и Oswald (заголовки, штампы), лицензия обоих OFL-1.1.
- Палитра «бумага на столе» (`src/styles/tokens.css`): все пары цветов текста проверены на WCAG AA (минимум 5.29:1).
- Сборка (`npm run build`) удаляет из `dist` боевые файлы прокси (`api/config.php`, `config.example.php`).
